## 二、核心概念

### 1. 镜像 Image

镜像是应用运行所需环境和文件的可复用模板，例如 `caddy:2-alpine`、`node:22-alpine`、PostgreSQL 和 Redis 镜像。通过 Dockerfile 可以把 Node.js 服务和运行命令固化为自定义镜像。

### 2. 容器 Container

容器是镜像启动后的运行实例。镜像负责提供基础环境，容器负责实际运行服务；同一个镜像可以启动多个容器实例。

### 3. Volume

Volume 用于保存容器生命周期之外的数据。今天的 Compose 示例使用 PostgreSQL 和 Redis Volume 保存数据，普通 `docker compose down` 不会删除数据，`down -v` 才会删除 Volume，因此删除数据前需要明确确认。

### 4. Network

Compose 会为服务创建网络，同一网络中的服务可以使用服务名互相访问，例如：

```text
api -> postgres:5432
api -> redis:6379
frontend -> api:3000
```

容器内部不能使用 `localhost` 访问其他服务，因为 `localhost` 指向当前容器本身。

## 三、今天完成的实践

### 1. Caddy 静态网页容器

`7.Docker/1.docker-hello` 使用 `docker run` 启动 Caddy，将本地 `site/` 以只读方式挂载到容器的 `/srv`，并将宿主机的 `8081` 映射到容器的 `80` 端口。

`7.Docker/3.caddy` 进一步把启动、停止、重启、更新、状态查看、日志查看和 Caddyfile 校验封装进 `caddy.sh`，形成了一个可重复执行的本地运维脚本。

### 2. Node.js HTTP 服务镜像

`7.Docker/3.dockerfile-node-http` 使用 `node:22-alpine` 作为基础镜像，通过 Dockerfile 复制 `index.js`，再以 `node index.js` 启动 HTTP 服务，并通过端口映射对外提供访问。

同时练习了镜像构建、标签、保存为 tar 文件、加载镜像，以及启动自定义镜像的基本流程。

### 3. Compose 多服务编排

`7.Docker/4.docker-compose` 将 PostgreSQL、Node.js 服务和 Caddy 放入同一个 `miaoma-net` 网络中，理解了多个容器如何协同工作。

`7.Docker/5.ai-docker-compose[仅演示 AI 生成]` 进一步形成了一个前端 + API + PostgreSQL + Redis 的完整演示：

- Caddy 提供前端静态页面并代理 `/api`。
- Node.js API 依赖 PostgreSQL 和 Redis。
- PostgreSQL 与 Redis 通过 Volume 保存数据。
- API 和数据库具备健康检查。
- `depends_on` 根据健康状态控制服务启动顺序。
- `start.sh` 和 `stop.sh` 固定启动、停止命令。

## 五、对 FDE 的价值

Docker 是把“代码能在本地运行”推进到“应用能够被标准化交付”的基础工具。对于后续 FDE 工作，今天的内容主要建立了以下能力基础：

- 能理解客户项目中的镜像、容器、网络、端口和数据持久化关系。
- 能快速判断服务之间为什么连不上，以及 `localhost` 和服务名的区别。
- 能将前端、后端和基础设施组合成可重复启动的开发环境。
- 能为 AI 应用准备 Node.js、数据库、缓存和反向代理等运行基础设施。
- 能通过健康检查和日志定位服务启动顺序、依赖和运行状态问题。
