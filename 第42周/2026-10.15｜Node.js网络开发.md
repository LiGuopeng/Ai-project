## 二、HTTP：Web 服务的基础

Node.js 的 `http` 模块既可以创建服务端，也可以作为客户端发起请求。

### HTTP 服务端

通过 `http.createServer()` 创建服务，并从请求对象和响应对象中处理一次请求：

- `req.headers`：请求头
- `req.method`：请求方法
- `req.url`：请求路径
- `res.setHeader()`：设置响应头
- `res.write()`：持续写入响应内容
- `res.end()`：结束响应

示例实现了响应头设置、状态码、分段响应和简单路径处理。HTTP 的基本模式是“客户端发起请求，服务端返回响应”。

### HTTP 客户端

通过 `http.request()` 和 `http.get()` 可以从 Node.js 主动访问外部服务，读取响应流并在 `end` 事件中处理完整结果。这类能力可用于：

- 调用第三方 API
- 爬虫和数据抓取
- 代理服务
- 访问内部微服务

## 三、Express：对原生 HTTP 的工程封装

Express 和 Fastify 是 Node.js 常见的 Web 服务框架，也可以作为 NestJS 底层的 HTTP 引擎。

相比原生 `http`，Express 提供了更清晰的路由和中间件模型：

- `app.get()`、`app.post()`：声明不同 HTTP 方法的路由
- `bodyParser.json()`：解析 JSON 请求体
- `bodyParser.urlencoded()`：解析表单数据
- `cors()`：处理跨域请求
- `app.use()`：注册日志、响应头和业务中间件
- `app.listen()`：启动服务

示例中实现了首页、用户、登录和 Markdown 路由，并通过中间件统一处理请求日志、请求体解析、跨域和响应头。

原生 HTTP 示例还展示了简单的 Controller/Service 分层：

```text
请求
  -> Controller 路由映射
  -> Service 业务逻辑
  -> 数据库 / 文件 / 外部服务
  -> Response
```

这也是 NestJS 等后端框架进一步抽象的基础。

## 四、SSE：服务端事件推送

SSE（Server-Sent Events）基于普通 HTTP 长连接，实现服务端向客户端的单向持续推送。

服务端需要设置：

```text
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

每条消息使用 `data:` 开头，并以空行 `\n\n` 作为消息结束标识。示例实现了：

- 连接成功后的初始消息
- 每秒推送一条带 ID 的消息
- 客户端断开时清理定时器
- 使用 `fetch`、`ReadableStream` 和 `TextDecoder` 手动解析流
- 处理网络分片和中文多字节字符

SSE 适合日志输出、AI 生成内容流式返回、进度通知和实时状态更新。它的特点是实现简单、基于 HTTP，但通信方向只有服务端到客户端。

## 五、WebSocket：双向实时通信

WebSocket 在 HTTP 握手之后升级为长连接，客户端和服务端都可以主动发送消息。

示例包含两种实现方式：

### 手动实现 WebSocket 握手

- 监听 HTTP Server 的 `upgrade` 事件。
- 读取 `Sec-WebSocket-Key`。
- 拼接 WebSocket 固定 GUID，通过 SHA-1 和 Base64 生成 `Sec-WebSocket-Accept`。
- 返回 `101 Switching Protocols` 响应，完成协议升级。
- 手动生成服务端 WebSocket 数据帧。

该示例帮助理解 WebSocket 的底层握手过程和数据帧结构，目前数据帧演示限制在不超过 125 字节的文本消息。

### 使用 `ws` 库

`ws` 封装了底层协议细节，通过 `WebSocketServer` 监听连接，再使用：

- `message`：接收客户端消息
- `send()`：向客户端发送消息
- `close`：清理定时器和资源
- `error`：处理连接错误

WebSocket 适合聊天、协同编辑、实时控制、在线状态和双向 AI Agent 交互。

## 六、TCP：可靠的传输层通信

TCP 不依赖浏览器的 HTTP 抽象，而是直接建立客户端和服务端之间的可靠连接。

服务端通过 `net.createServer()` 接收连接，客户端通过 `net.createConnection()` 建立连接。示例实现了：

- TCP 服务端监听 `8080` 端口
- 客户端每秒发送递增数字
- 服务端监听 `data` 事件读取数据
- 服务端向客户端返回确认消息
- 客户端监听连接错误和关闭事件

TCP 保证连接可靠、有序，但它本身不定义消息边界，因此应用层需要自行设计协议，例如使用换行符、长度字段或 JSON framing 区分完整消息。

## 七、UDP：无连接的数据报通信

UDP 通过 `dgram.createSocket("udp4")` 创建 Socket，客户端使用 `send()` 发送数据报，服务端使用 `bind()` 监听端口，并通过 `message` 事件接收消息。

示例实现了：

- UDP 服务端绑定本地 `8080` 端口
- 客户端每秒发送递增数字
- 服务端读取消息内容
- 通过 `rinfo` 获取客户端地址和端口
- 连接关闭时清理定时器

UDP 不需要建立连接，开销小、速度快，但不保证数据一定到达、顺序正确或只到达一次，适合对实时性要求高、可以容忍丢包的场景。

## 八、协议对比

| 技术 | 通信关系 | 可靠性 | 典型场景 |
| --- | --- | --- | --- |
| HTTP | 请求—响应 | 可靠、有边界 | Web API、页面、普通服务调用 |
| SSE | 服务端单向推送 | 基于 HTTP | AI 流式输出、日志、进度通知 |
| WebSocket | 客户端与服务端双向 | 长连接、实时 | 聊天、协同、实时状态 |
| TCP | 客户端与服务端连接 | 可靠、有序 | 自定义协议、长连接服务 |
| UDP | 客户端与服务端数据报 | 不保证送达和顺序 | 实时广播、低延迟数据传输 |

选择协议时，重点考虑通信方向、是否需要连接、可靠性要求、延迟、消息边界和实现复杂度。

## 九、与 AI 项目的关系

网络层是 AI 应用连接用户、模型和外部系统的基础：

```text
用户请求
  -> HTTP / WebSocket 接入
  -> Node.js 服务编排
  -> 调用模型、MCP 或其他服务
  -> SSE / WebSocket 流式返回
  -> 客户端实时展示结果
```

- 普通 API 请求适合 HTTP。
- 模型生成过程适合 SSE 或 WebSocket 流式传输。
- 多 Agent 实时协作可以使用 WebSocket。
- 服务之间的特殊高性能通信可以考虑 TCP 或 UDP。
- Express 和 NestJS 负责把底层网络能力组织成可维护的业务服务。

## 十一、核心心得

1. HTTP 是应用层最常见的请求—响应协议，Express 和 NestJS 是对它的工程化封装。
2. SSE、WebSocket、TCP 和 UDP 解决的是不同的通信需求，不能只按“哪个更快”选择。
3. SSE 适合服务端单向推送，WebSocket 适合真正的双向实时通信。
4. TCP 可靠但需要自己设计消息边界，UDP 轻量但需要业务接受丢包和乱序。
5. 网络服务不仅要关注“能不能连通”，还要处理断开、错误、资源清理和消息协议。
6. AI 应用中的流式输出、实时 Agent 状态和工具调用，都建立在这些网络基础之上。
