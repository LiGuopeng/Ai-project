# 第 42 周｜5.node-basic｜Node.js 运行时与核心模块｜2026 年 10 月 13 日

## 一、学习主题

本节围绕 Node.js 运行时和常用核心模块展开，目标是理解 Node.js 如何访问文件系统、识别运行环境、读取进程信息，以及调用外部命令和其他程序。

Node.js 基于 V8 JavaScript 引擎，除了开发 Web 服务和 RESTful API，也可以用于：

- 实时通信和微服务
- 命令行工具
- AI Agent 的执行内核
- 调用 Python、FFmpeg、Codex、MCP 等外部程序

在 AI-Native 开发中，Node.js 不只是一个后端框架基础，也是编排不同语言、工具和 Agent 的重要运行时。

## 二、Node.js 工程基础

- 使用 `nvm`、`volta`、`n` 或 `fnm` 管理 Node.js 多版本。
- 使用 `package.json` 描述项目元信息、入口、依赖和脚本。
- 使用 `npm init` 初始化项目，使用 `node index.js` 执行 JavaScript 文件。
- 使用 `pnpm` 管理依赖和工作区。
- 通过 `scripts` 将构建、开发和重复工作固定为可执行命令。

### package.json 关键字段

| 字段 | 作用 |
| --- | --- |
| `dependencies` | 生产环境依赖 |
| `devDependencies` | 开发、构建和测试依赖 |
| `peerDependencies` | 宿主项目需要提供的依赖，常见于组件库 |
| `scripts` | 项目工作流命令 |
| `main` | CommonJS 入口 |
| `module` | ESM 入口 |
| `bin` | 命令行程序入口 |
| `types` | TypeScript 类型入口 |
| `type` | 声明项目采用 CommonJS 或 ESM 模块体系 |

## 三、模块化与 TypeScript

Node.js 主要涉及两种模块规范：

- CommonJS：使用 `require` 和 `module.exports`。
- ESM：使用 `import` 和 `export`。

项目当前配置了 `"type": "module"` 和 `module: "nodenext"`，采用 ESM 方式组织 TypeScript 代码。实际项目中需要注意不同第三方包的模块格式兼容问题。

TypeScript 项目采用“源码目录 → 编译目录”的方式：

```text
src/*.ts
  -> tsc
  -> dist/*.js
```

当前配置还开启了严格类型检查、声明文件、Source Map 和 Node 类型支持，体现了工程项目中“先编译、再运行”的基本方式。

## 四、核心模块实践

### 1. `fs`：文件系统

用于读取、写入、删除和查看文件信息：

- `readFile` / `readFileSync`：读取文件
- `writeFile`：写入文件
- `unlink`：删除文件
- `stat`：获取文件或目录信息
- `node:fs/promises`：使用 Promise 风格操作文件
- `promisify`：将回调 API 转换成 Promise API

实践重点是使用绝对路径，结合 `import.meta.dirname` 和 `path` 生成可靠的文件路径。文件操作通常优先使用异步方式，避免阻塞 Node.js 主线程。

### 2. `path`：路径处理

用于跨平台地拼接、解析和拆分文件路径：

- `path.join()`：拼接路径
- `path.resolve()`：解析为绝对路径
- `path.basename()`：获取文件名
- `path.dirname()`：获取目录名
- `path.extname()`：获取扩展名

相比手写字符串拼接，使用 `path` 模块可以减少不同操作系统之间的路径兼容问题。

### 3. `os`：系统信息

用于读取运行 Node.js 的操作系统和硬件信息：

- CPU 架构和操作系统平台
- CPU 数量和详细信息
- 空闲内存与总内存
- 用户主目录
- 系统运行时间

这些能力可用于环境检测、性能监控、资源判断和跨平台逻辑。

### 4. `process`：进程信息

`process` 是 Node.js 与运行环境交互的核心对象，示例涉及：

- `process.argv`：读取命令行参数
- `process.env`：读取环境变量
- `process.cwd()`：获取当前工作目录
- `process.memoryUsage()`：查看进程内存占用
- `process.exit()`：退出进程
- `process.nextTick()`：安排下一轮事件循环任务

配合 `dotenv` 可以读取本地环境变量。生产环境还需要使用更安全、受控的配置管理方式，不能把密钥直接写入代码。

### 5. `child_process`：子进程

用于从 Node.js 启动外部命令、脚本和其他程序：

- `spawn()`：适合流式处理标准输入输出，也是当前实践重点。
- `exec()`：适合执行命令并一次性获取输出。
- `fork()`：适合启动另一个 Node.js 进程并进行进程间通信。

典型场景包括：

- 调用 FFmpeg 处理视频
- 调用 Codex 或其他命令行工具
- 在 Node.js 服务中调用 Python Agent
- 拆分可能阻塞或崩溃的任务
- 并行执行多个 Agent 或后台任务

## 五、与 AI 项目的关系

Node.js 的重要价值在于“编排”：

```text
Node.js 服务
  -> 读取用户输入和环境变量
  -> 组织文件与路径
  -> 调用 Codex / Python / FFmpeg / MCP
  -> 流式接收子进程输出
  -> 汇总结果并返回给用户
```

因此，Node.js 基础不仅是学习语法，更是在学习如何把操作系统能力、外部工具和 AI Agent 组合成完整应用。

## 七、核心心得

1. Node.js 的核心能力不只是启动 HTTP 服务，还包括文件、进程、系统和外部命令编排。
2. `package.json` 和脚本是项目工程化的入口，应把重复流程固定下来。
3. 文件路径必须使用 `path` 处理，环境配置必须通过环境变量管理。
4. `spawn`、`exec` 和 `fork` 的选择取决于输出方式、通信需求和进程隔离要求。
5. AI Agent 产品往往需要 Node.js 作为协调层，连接模型、MCP、Python 服务和系统工具。
6. 学习基础模块时，不能只记 API，还要理解异步、进程、流式输出和错误处理。
