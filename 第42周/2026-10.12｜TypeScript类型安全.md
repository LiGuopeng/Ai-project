## 一、学习主题

本节围绕 TypeScript 类型系统、类型安全和工程化构建展开，目标是理解 TypeScript 如何约束 JavaScript 代码，并为全栈开发、Monorepo 和 AI 辅助编程提供更可靠的代码基础。

TypeScript 的价值不只是给变量增加类型，而是通过类型系统提前表达业务规则、接口契约和数据结构，减少运行时错误，也让 AI 生成的代码拥有更明确的边界。

## 二、TypeScript 工程基础

- TypeScript 源码需要编译为 JavaScript 才能在运行环境中执行。
- 编译过程还可以生成 `.d.ts` 类型声明文件和 Source Map。
- 传统构建工具包括 `tsc`、Babel、Webpack、Vite 和 esbuild。
- 当前工程实践使用 `tsdown`，通过配置文件统一处理 TypeScript 打包和类型声明生成。
- 常见工程配置文件包括 `package.json`、`tsconfig.json` 和 `tsdown.config.ts`。

当前示例采用以下构建链路：

```text
src/*.ts
  -> tsdown
  -> dist/*.mjs
  -> dist/*.d.mts + Source Map
```

## 三、基础类型

示例覆盖了 TypeScript 常见基础类型：

- `boolean`、`number`、`string`
- 数组类型和泛型数组类型
- 元组类型
- 枚举类型
- `any`、`unknown`
- `void`、`null`、`undefined`
- `never`

其中需要重点区分：

- `any` 会放弃类型检查，应谨慎使用。
- `unknown` 表示未知类型，但在使用前必须进行类型判断，更安全。
- `never` 表示不会正常返回的值，例如抛出异常或永不结束的函数。

## 四、自定义类型与面向对象类型

### `type`

适合声明对象结构、联合类型、交叉类型和类型计算结果。例如使用 `type User` 描述用户对象。

### `interface`

适合描述对象或类需要遵循的结构，可以声明方法和属性，并被类通过 `implements` 实现。

### `class`

不仅描述类型，也可以包含构造函数、属性和方法，适合需要运行时实例行为的场景。

学习重点是理解 `type`、`interface` 和 `class` 的职责差异：前两者主要服务于类型约束，`class` 同时承担运行时对象实现。

## 五、联合类型与交叉类型

### 联合类型 `|`

联合类型表示一个值可以属于多个类型之一，适合表达不同业务形态的集合。例如文本块和图片块可以组成统一的 `Block` 类型。

### 交叉类型 `&`

交叉类型表示一个值同时满足多个类型，适合组合多个对象协议。例如把 `id` 和 `name` 两个结构合并成一个完整对象。

联合类型解决“多种可能”，交叉类型解决“能力组合”。实际使用时通常需要配合类型保护来判断联合类型的具体分支。

## 六、泛型

泛型用于表达“类型由使用者决定，但类型关系仍然保持”的场景。

示例包括：

- 泛型函数，根据参数类型返回对应的元组类型。
- 泛型类，让用户对象的 ID、名称或其他字段拥有可配置类型。
- 泛型接口，使同一套结构可以适配不同的数据类型。

泛型相比直接使用 `any` 更安全，因为它保留了输入和输出之间的类型关系。它是封装通用 API、请求响应、数据容器和组件库的基础能力。

## 七、内置工具类型与类型编程

示例使用并手动实现了常见工具类型：

- `Pick`：从类型中选择部分字段。
- `Omit`：从类型中排除指定字段。
- `Record`：根据键集合构造对象类型。
- `Partial`：将所有字段变为可选。
- 进一步学习 `Required`、`Readonly`、`NonNullable`、`Exclude` 和 `Extract`。

通过 `keyof`、映射类型和条件类型，实现了 `MiaomaPick`、`MiaomaOmit`、`MiaomaRecord` 和 `MiaomaPartial`。这说明 TypeScript 不只是声明类型，还可以对类型进行计算和变换。

## 八、类型保护

联合类型在实际业务中需要先确认具体类型，再安全地访问对应能力。示例通过自定义类型谓词实现类型保护：

```ts
function isNumber(value: number | string): value is number {
  return typeof value === "number";
}
```

类型保护可以使用 `typeof`、`instanceof`、属性判断和自定义谓词。它让 TypeScript 在分支内部准确收窄类型，避免直接断言带来的运行时风险。

## 九、条件类型与 `infer`

条件类型可以根据类型是否满足某个条件返回不同结果：

```ts
type IsMan<T> = T extends "man" ? true : false;
```

`infer` 用于在条件类型中提取隐藏的类型信息。示例实现了：

- 从函数类型中提取参数元组。
- 从元组类型中提取第一个元素。
- 根据输入类型推导输出结果。

这类能力常见于框架类型、路由定义、API 契约、响应包装器和工具库，是 TypeScript 高级类型编程的基础。

## 十、装饰器

示例开启了 `experimentalDecorators`，展示了类装饰器、属性装饰器和方法装饰器。

装饰器可以在不直接修改原有业务代码的情况下，为类、属性和方法增加日志、注册、校验或元数据能力。其思想接近面向切面编程，在 NestJS 等框架中广泛使用。

使用装饰器时要注意：装饰器涉及运行时行为和编译配置，不能只把它当成普通语法糖，还需要理解执行时机、装饰目标和元数据机制。

## 十一、TypeScript 与 AI 全栈开发

TypeScript 对 AI 辅助编程的价值主要体现在：

- 用类型约束减少 AI 生成代码的自由度。
- 用接口和联合类型明确前后端数据契约。
- 用工具类型快速生成 DTO、响应类型和视图模型。
- 用泛型封装通用请求、状态和组件逻辑。
- 用严格编译和声明文件尽早发现错误。
- 用 Monorepo 共享类型，减少多端实现不一致。

可以形成如下工作方式：

```text
定义业务类型
  -> 设计接口契约
  -> 生成前后端实现
  -> 编译检查
  -> 测试验证
  -> 共享类型与持续迭代
```

## 十三、核心心得

1. TypeScript 的核心价值是用类型表达业务规则，而不是简单给变量标注类型。
2. `unknown`、联合类型、类型保护和泛型是编写安全业务代码的关键组合。
3. 工具类型、条件类型和 `infer` 让类型本身具备可组合、可计算和可复用能力。
4. 接口契约和共享类型是全栈、跨端和 Monorepo 协作的基础。
5. 对 AI 来说，越明确的类型和工程规范，越容易生成可维护、可验证的代码。
6. 类型检查只能减少一类问题，仍然需要测试、运行验证和人工判断。
