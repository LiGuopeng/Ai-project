# Test Planning

## 适用范围

当用户需要从需求或现有产品规划测试、拆解测试场景、设计端到端覆盖或审查测试遗漏时使用。该 Skill 负责规划，不直接替代测试脚本生成。

## 工作流程

1. 读取 PRD、验收标准、OpenAPI、页面结构和已有测试，标记事实、假设与缺失信息。
2. 建立需求到测试的追溯矩阵，覆盖核心流程、异常流程、边界值、权限、并发、网络失败和数据隔离。
3. 按风险和优先级拆分测试场景，明确前置条件、测试数据、环境、操作步骤、预期结果和清理方式。
4. 区分单元、接口、集成、端到端、探索式和人工体验测试，避免所有问题都用 UI 测试解决。
5. 标记可自动化、需要人工审核和本期不适用的场景，并说明原因。
6. 输出计划后进行人工评审，再交给测试生成流程实现。

## 输出要求

- 测试范围与不测范围
- 风险分级和优先级
- 需求—场景追溯矩阵
- 测试数据、账号、权限和环境要求
- 正常、异常、边界和恢复场景
- 自动化建议、人工审核点和通过标准

## 质量门槛

- 每条 P0/P1 需求至少有成功路径和关键失败或边界路径。
- 不以测试数量代替覆盖质量。
- 测试计划不能依赖不存在的页面元素、接口或业务规则。
- 每个场景都能被其他人依据文档复现和判断结果。
