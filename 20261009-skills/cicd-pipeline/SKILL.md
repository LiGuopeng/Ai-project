# CI/CD Pipeline

## 适用范围

当用户需要生成或改造 GitHub Actions、GitLab CI、Docker 构建、制品发布、测试环境部署或生产发布流程时使用。只要求本地构建命令时，不必扩展为完整生产流水线。

## 工作流程

1. 盘点项目语言、包管理器、构建入口、测试命令、制品类型、环境和部署目标。
2. 设计流水线阶段：代码检查、依赖安装、单元/集成测试、构建、制品归档、部署、发布后验证。
3. 固定 Node、Java、Python、Docker 和依赖版本，使用缓存时确认不会污染构建结果。
4. 将密钥、环境变量和生产配置与代码分离，禁止把 Token、密码、私钥或真实域名写入仓库。
5. 为部署增加健康检查、冒烟测试、灰度策略、失败停止条件和可执行回滚方案。
6. 先校验 YAML、Docker Compose 和构建脚本，再在非生产环境运行；未经明确授权不得执行生产发布或修改线上资源。

## 输出要求

- CI/CD 配置文件
- 触发条件、分支策略和环境变量清单
- 构建制品和版本标识规则
- 测试门禁与发布前检查
- 部署、灰度、监控和回滚 Runbook
- 流水线验证结果和已知风险

## 质量门槛

- 每个发布制品可追溯到提交、版本和构建日志。
- 测试失败、构建失败和健康检查失败时，流水线必须停止或进入明确的回滚路径。
- 生产密钥只通过受控环境注入，日志不得泄露敏感信息。
- 不把“脚本已生成”写成“部署已成功”，必须提供实际运行证据。
