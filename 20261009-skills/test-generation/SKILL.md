# Test Generation

## 适用范围

当已有测试计划或明确验收标准，需要生成 Vitest、Jest、Supertest、Playwright 等测试代码时使用。没有需求依据时先退回测试规划，不凭空扩展业务规则。

## 工作流程

1. 读取已审核的测试计划，确认测试框架、运行命令、环境、数据工厂和清理策略。
2. 优先使用真实 DOM、OpenAPI 和代码契约生成测试；先验证页面元素、接口字段和状态码，再写断言。
3. 按测试计划逐步生成脚本，保证每个用例独立、可重复、可定位失败。
4. 运行测试并区分产品缺陷、测试缺陷、环境问题和数据问题，不能把失败直接判定为业务 Bug。
5. 对 UI 未变化但选择器或等待方式失效的问题执行 Healer 修复；如果业务规则或需求发生变化，停止自动修复并请求人工判断。
6. 输出测试报告、失败分类、未覆盖风险和接入 CI 的命令。

## 强制规范

- Playwright 定位优先级：`getByRole` > `getByLabel` > `getByText` > 稳定的 `data-testid` > CSS。
- 禁止使用固定 `waitForTimeout` 代替可观察状态等待。
- 每个用例独立准备数据、登录状态和清理数据，不依赖执行顺序。
- 接口测试覆盖成功、参数校验、权限和异常响应。
- 测试通过必须以实际运行结果为准，不能只依据代码审查或生成成功。

## 输出要求

- 测试脚本和必要的测试数据工厂
- 运行命令和依赖说明
- 通过、失败和跳过结果
- 失败原因分类和修复建议
- 未覆盖场景与人工确认事项
