# Technical Learning

## 适用范围

当用户要学习新的编程语言、框架、基础设施、AI 工具或进行技术选型比较时使用。单纯要求实现一个已经熟悉的功能时，不必生成完整学习路线。

## 工作流程

1. 明确学习目标、已有基础、最终要交付的功能和时间约束。
2. 建立概念地图：核心抽象、运行模型、目录结构、依赖管理、调试方式和常见陷阱。
3. 选定一个最小可运行示例，优先使用用户真实项目中的场景，而不是孤立的语法练习。
4. 先建立接口、数据模型和运行命令，再逐步实现功能；每一步都解释为什么这样设计。
5. 通过类型检查、测试、构建和运行结果验证学习内容，记录失败原因和修复方式。
6. 对比已有技术栈的相同概念，沉淀术语表、决策记录和下一步练习。

## 输出要求

- 学习目标和前置知识
- 概念与术语地图
- 最小可运行项目或代码示例
- 关键设计决策和替代方案
- 可执行命令与验证结果
- 常见问题、风险和继续学习路径

## 质量门槛

- 示例必须能运行或明确说明未验证的原因。
- 不把框架默认配置、猜测 API 或版本特性当成事实。
- 技术选型至少说明适用场景、代价、迁移影响和放弃理由。
- 以真实项目中的可观察结果检验是否学会，而不是只背概念。
