## 一、今日学习主题

今天围绕 `10.nest-action-notes` 展开 NestJS 服务端开发实战，将前面学习的 NestJS 模块化、依赖注入、PostgreSQL 和 Docker 知识，进一步落到 ORM、JWT 认证和文件上传场景。

本次内容包括：

- NestJS 环境配置与配置注入。
- TypeORM 连接 PostgreSQL 和实体关系映射。
- Prisma Schema、Migration 和数据库访问。
- JWT 登录、Bearer Token 和接口保护。
- Multer 文件上传、静态资源访问和文件限制。
- Swagger 自动化接口文档。
- Docker PostgreSQL 端口和数据目录配置。
- 构建、单元测试以及当前工程问题验证。

## 二、项目实践路线

`10.nest-action-notes` 下的项目按照由浅入深的方式推进：

1. `1.nest.config`：学习 `ConfigModule` 和环境变量配置。
2. `2.nest-orm`：使用 TypeORM 将对象映射为 PostgreSQL 数据表。
3. `3.nest-prisma-jwt`：使用 Prisma 完成数据库访问，并增加 JWT 认证。
4. `4.nest-file-uploader-demo`：学习 Multer 文件接收和 Swagger 文档。
5. `5.miaoma-file-uploader`：实现可直接运行的本地文件上传服务。

这条路线将之前的 NestJS 基础知识串联成了一个实际后端开发流程：

```text
配置
  -> 数据库
  -> ORM
  -> 用户认证
  -> 文件服务
  -> 接口文档
```

## 三、NestJS 配置管理

`1.nest.config` 使用 `ConfigModule.forRoot` 加载环境文件，并通过自定义配置函数组织数据库配置。

当前已经理解：

- `.env` 可以保存不同环境下的配置。
- `ConfigModule` 可以统一管理环境变量。
- 自定义配置函数可以将环境变量转换为结构化配置。
- Service 可以通过 `ConfigService` 获取配置。
- 应用端口、数据库地址和第三方服务配置不应该散落在业务代码中。

当前实现仍是学习版本：

- `envFilePath` 主要加载 `.env` 和 `.env.example`。
- `.env.prod` 尚未形成真正的生产环境切换机制。
- TypeORM 项目和部分数据库配置仍然直接写在模块代码中。
- 数据库账号密码还需要进一步改为统一环境变量注入。

## 四、TypeORM 与 PostgreSQL

`2.nest-orm` 使用 TypeORM 连接 PostgreSQL，并通过 Entity 描述数据表。

主要实践包括：

- 使用 `TypeOrmModule.forRoot` 建立数据库连接。
- 使用 `TypeOrmModule.forFeature` 注入 Repository。
- 创建 `User`、`Photo` 和 `UserDetail` 实体。
- 实践一对多和一对一关系。
- 通过 Repository 执行统计、查询和保存操作。
- 理解“程序对象映射为数据库表”的 ORM 模式。

结合之前 PostgreSQL 容器化排查的经验，本项目还涉及：

- PostgreSQL 宿主机端口配置。
- PostgreSQL 18 数据目录挂载。
- Docker Compose 启动和连接配置。
- 容器端口与宿主机端口的区别。

当前需要注意：

- 数据库连接信息仍有硬编码。
- `synchronize: true` 只适合开发环境。
- 目前主要是演示接口，还没有完整 CRUD。
- 真实数据库连接和 HTTP 端到端流程还需要继续验证。

## 五、Prisma 与 JWT 认证

`3.nest-prisma-jwt` 在 TypeORM 的基础上切换到 Prisma，并加入 JWT 认证能力。

Prisma Schema 定义了：

- `User`
- `Photo`
- `UserDetail`

主要实践包括：

- 使用 Prisma Schema 描述数据库模型。
- 使用 Migration 管理数据库结构。
- 封装全局 `PrismaService`。
- 在模块销毁时断开数据库连接。
- 使用 Prisma Client 查询和创建用户。
- 通过 `POST /auth/login` 签发 JWT。
- 通过 `GET /auth/profile` 验证 Bearer Token。
- 使用 Passport JWT Strategy 解析和校验 Token。

当前实现仍是演示版本：

- 用户密码使用明文比对，正式项目必须使用密码哈希。
- 登录请求还没有 DTO 和参数校验。
- JWT Secret 提供了默认值，生产环境必须强制从安全配置中读取。
- 用户名还没有设置唯一约束。
- 尚未完成登录、携带 Token 访问受保护接口的完整 HTTP 验证。

## 六、文件上传与 Swagger

`4.nest-file-uploader-demo` 主要用于学习 Multer 和 Swagger。

核心内容包括：

- 使用 `FileInterceptor('file')` 接收文件。
- 理解 `multipart/form-data` 请求。
- 文件表单字段名必须与拦截器保持一致。
- 使用 Swagger 自动生成接口文档。
- 通过 `/api` 查看接口文档。

`5.miaoma-file-uploader` 进一步实现了本地文件上传服务：

- 使用 `diskStorage` 保存文件。
- 自动创建 `uploads` 目录。
- 单文件最大限制为 10 MB。
- 仅允许 JPG、PNG 和 PDF。
- 清理原始文件名中的特殊字符。
- 使用时间戳生成新文件名。
- 通过 `/uploads` 提供静态文件访问。
- 返回文件名、类型、大小和访问 URL。

这与总笔记中的文件存储路线一致：

```text
学习阶段：保存到本地服务器
生产阶段：上传 OSS，仅保存对象 Key 和文件元数据
```

已经形成的连接关系是：

- Docker Compose 提供 PostgreSQL 服务。

当前目录主要实践了 PostgreSQL，Redis 还没有真正接入 NestJS 业务代码。后续可以将 Redis 用于登录会话、Token 黑名单、文件上传任务状态、缓存和 Bull 队列。
