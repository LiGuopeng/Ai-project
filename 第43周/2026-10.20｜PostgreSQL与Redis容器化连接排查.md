## 二、第一次错误：5432 端口已被占用

最初启动 Compose 时出现：

```text
Bind for 0.0.0.0:5432 failed: port is already allocated
```

排查发现宿主机的 `5432` 已被 `8.nest-basic-notes/3.custom-module` 项目的 PostgreSQL 容器 `nest--lgp-db-1` 占用；`6379` 同时被 `miaoma-lgp-redis` 占用。

这说明多个学习项目使用了相同的宿主机端口。处理这类问题时，不能只看当前 Compose 文件，还需要查看所有运行中的容器和宿主机监听端口：

```bash
docker ps
lsof -nP -iTCP:5432 -sTCP:LISTEN
```

宿主机端口可以修改，例如将 `5432:5432` 改为 `5433:5432`；但容器之间通信仍应使用服务名和容器内部端口 `5432`。

## 三、第二次错误：Connection refused

端口冲突处理后，客户端出现：

```text
PostgreSQL connection failed:
Connection refused (os error 61)
```

继续检查发现 PostgreSQL 容器 `miaoma-lgp-services` 处于 `Exited (1)`，因此应用连接不到数据库。此时问题已经不是用户名、密码或 SQL，而是数据库服务根本没有保持运行。

排查顺序应该是：

```text
连接失败
  -> 查看容器状态
  -> 查看数据库日志
  -> 确认进程是否监听端口
  -> 再检查客户端连接配置
```

## 四、根因：PostgreSQL 18 数据目录挂载方式变化

容器日志明确提示：`postgres:18-alpine` 使用了 PostgreSQL 18 的版本化数据目录结构，但原配置将宿主机目录挂载到：

```yaml
- ./postgresql_data:/var/lib/postgresql/data
```

PostgreSQL 18 官方镜像建议将整个 PostgreSQL 数据目录挂载到：

```yaml
- ./postgresql_data:/var/lib/postgresql
```

容器内部实际数据位于类似下面的路径：

```text
/var/lib/postgresql/18/docker
```

如果仍然把数据挂载到 `/var/lib/postgresql/data`，镜像会识别到该位置存在或可能存在旧数据，但当前启动方式不会使用它，于是拒绝启动，最终导致上层应用收到 `Connection refused`。

这次问题的关键不是简单地“重启容器”，而是识别镜像版本和数据目录约定之间的不兼容。

## 五、Compose 环境

当前 Compose 示例包含两个服务：

- `miaoma-lgp-services`：`postgres:18-alpine`，宿主机端口 `5432`。
- `miaoma-lgp-redis`：`redis:8.4`，宿主机端口 `6379`。

PostgreSQL 使用本地目录保存数据，Redis 当前未启用 Volume。数据库配置为：

```text
用户：lgp
密码：lgp
数据库：postgres
```

Compose 配置解析可以通过，但配置解析通过只代表 YAML 和变量结构有效，不代表数据库进程一定能成功启动。数据库类服务还需要结合容器日志和实际连接进行验证。

## 六、启动结果验证

修正 PostgreSQL 18 的挂载路径后，容器日志显示：

```text
database system is ready to accept connections
```

这证明 PostgreSQL 曾经成功启动并监听：

```text
0.0.0.0:5432
:: :5432
```

随后容器收到正常的 `fast shutdown request`，日志显示数据库完成 checkpoint 并正常关闭，不是启动崩溃。

当前准确结论：

- Compose 配置可以解析。
- PostgreSQL 18 已成功启动并接受过连接。
- PostgreSQL 数据目录已经按 18 版本结构生成。
- 当前容器处于停止状态，后续使用 `docker compose up -d` 即可重新启动。
- 还没有形成一次完整的“启动后执行 SQL、Node.js 查询、Redis 读写”的闭环记录。

## 七、Node.js 客户端实践

`9.pg-redis-notes/2.node-server` 使用 TypeScript 编写两个客户端示例：

### PostgreSQL

使用 `pg.Pool` 连接本机 PostgreSQL：

```text
host: 127.0.0.1
port: 5432
user: lgp
database: postgres
```

示例通过连接池执行 `SELECT * FROM article`，并预留了插入文章、全文检索、索引、事务和并发控制等后续学习内容。

### Redis

使用 `redis.createClient` 连接本机 `6379`，读取 `user:name` 缓存键，开始实践 Redis 客户端连接和读取操作。

后续需要注意 Compose 中的 Redis 密码配置和客户端 URL 是否一致。仅设置 `REDIS_PASSWORD` 环境变量，不一定会让 Redis 服务自动启用密码认证，需要明确配置 Redis 启动参数或认证方式。
