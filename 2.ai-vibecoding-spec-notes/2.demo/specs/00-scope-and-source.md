# 规范范围与来源

## 1. 文档定位

本目录存放当前项目的工程化细则。内容来自对 `../1.basic/todo-app` 的目录、配置、脚本、前后端源码和开发流程的审阅，但只抽取可迁移的工程约束，不把其中的领域名称、页面、接口或数据字段升级为当前项目规则。

`AGENTS.md` 负责总入口、优先级和通用工作流；本目录负责可执行细节。新增规则应放入最贴近主题的文件，并在主入口中登记。

本目录中的规则默认必须执行。只有用户明确授权，或先修改规则文件并说明迁移原因，才能偏离规则。参考工程的实现方式不能自动成为当前项目的可选替代方案。

## 2. 抽取出的工程基线

- Monorepo：pnpm workspace + Turborepo。
- 前端基线：React、Vite、路由、服务端状态管理和统一 HTTP 客户端。
- 服务端基线：模块化框架、ORM、关系数据库、输入校验、认证和 API 文档。
- 共享能力：平台无关类型包、共享 UI 包和单一公开入口。
- 质量工具：TypeScript、ESLint、Prettier、CSpell、Husky、lint-staged 和 Commitlint。

## 3. 约束与示例的区别

必须保留的是包边界、分层方向、依赖管理、配置来源、质量门禁、提交格式、API 契约意识和敏感信息处理。具体领域、业务流程、端口、包名、服务名和接口路径都属于参考工程上下文，不能直接写入通用规则。

所有持久化业务数据都必须使用后端 API 和数据库；浏览器存储、内存数据、mock 或静态 JSON 不得作为正式数据源。

## 4. 变更规则

如果当前项目已有自己的配置、脚本或目录约定，以当前项目实际配置为准；不要机械复制参考工程的版本、名称或部署参数。规则不再适用时，修改 `AGENTS.md` 和对应 Spec，并在提交说明中记录原因。
