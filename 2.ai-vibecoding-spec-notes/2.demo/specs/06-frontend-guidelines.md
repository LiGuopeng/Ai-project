# 前端实现规范

## 1. 启动与入口

前端入口负责全局样式、框架 Provider、路由和全局错误边界的装配；根组件只负责布局出口，不承载具体请求。开发服务器、代理和环境变量必须集中配置，并在文档中说明。

## 2. 路由与页面

路由集中在 `src/router/`，公开页面、受保护页面和错误页面明确区分。访问控制统一由路由层或布局层处理；导航使用 Router API，不在业务代码中直接修改 location。每个页面使用独立目录，页面只负责编排，不直接实现基础设施。

## 3. 请求与状态

统一使用一个 HTTP 客户端，集中配置 baseURL、超时、凭证、响应转换和错误处理。资源请求拆分到 `services/`，不在 JSX 中直接调用底层客户端。服务函数明确输入和返回类型，异步页面必须处理 loading、success、error 和空数据状态。

服务端状态使用项目约定的缓存/请求方案；组件本地状态只保存表单值和 UI 状态。跨组件复用的逻辑下沉到 hooks，不重复实现凭证读取、错误解析或请求配置。

涉及服务端数据的功能必须通过 API 请求完成首次加载和所有增删改操作。不得在 hook 或组件中把 `localStorage`、`sessionStorage`、内存数组或静态 JSON 当作服务端数据的替代品。

## 4. 组件边界

页面负责编排，通用组件负责展示和事件转发，基础 UI 组件放入共享 UI 包。共享 UI 不依赖具体页面、路由、后端 service 或领域流程；业务组件可以组合共享 UI，但不应复制其样式和交互。

## 5. 可用性与错误处理

表单提交必须阻止默认行为，展示提交中状态，成功后明确反馈，失败后显示可理解提示。输入使用合适的原生语义和可访问属性。加载、错误、空数据、重复提交和网络失败都必须有可感知的界面反馈。
