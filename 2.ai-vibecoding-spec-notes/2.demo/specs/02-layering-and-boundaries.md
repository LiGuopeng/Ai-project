# 分层与边界规范

## 1. 前端分层

适用于采用 React 或类似组件模型的前端应用：

| 目录 | 职责 | 边界 |
| --- | --- | --- |
| `pages/` | 页面级组件 | 负责页面编排，不直接散落请求实现 |
| `components/` | 业务通用组件 | 单一职责，不持有基础设施配置 |
| `hooks/` | 可复用交互和状态逻辑 | 下沉复杂逻辑，避免页面堆积 |
| `services/` | HTTP/API 请求 | 按资源或能力拆分，统一使用客户端 |
| `types/` | API 和领域类型 | 优先从共享包导出，禁止重复定义 |
| `router/` | 路由和访问控制 | 集中配置，统一处理受保护入口 |
| `utils/` | 无副作用工具函数 | 不依赖页面、路由或组件状态 |
| `layout/`、`views/`、`blocks/` | 布局、视图组合、块级能力 | 仅在确有复杂度时新增 |

依赖方向应为页面/组件 -> hooks/services/types/utils；请求、鉴权、缓存和错误转换不得在多个页面重复实现。

持久化数据流必须为：页面/组件 -> hooks -> `services/` -> 后端 API -> 数据库。页面、组件和 hooks 不得直接读取或写入 `localStorage`、`sessionStorage`、IndexedDB 或数据库；临时 UI 偏好除外。

## 2. 服务端分层

- `modules/`：按领域或能力拆分的模块。
- `entities/`：持久化实体和关系定义。
- `fundamentals/`：异常处理、队列、定时任务、数据库适配等公共基础设施。
- `config/`：配置加载和环境映射。
- `pipes/`、`middleware/`、`guards/`：输入转换、请求预处理和访问控制。
- `utils/`：无明确领域归属的纯工具。

Controller 只负责路由、参数和访问控制；Service 负责业务编排和数据访问；Entity 只描述持久化模型；DTO/Schema 负责输入输出约束。模块之间通过公开接口协作，禁止直接引用其他模块的私有实现。

## 3. 共享包边界

平台无关包只承载类型、协议、领域定义和纯逻辑，不依赖具体 UI 或应用。UI 包只承载展示层能力，不负责 API 请求、路由和具体领域流程。每个包从单一入口导出，消费方不得依赖源码内部路径。

## 4. API 边界

前端通过 `services/` 访问服务端；服务端通过 DTO/Schema、统一异常处理和文档保护边界；共享类型用于减少契约漂移。修改接口时同步更新输入模型、输出类型、服务封装、调用方和 API 文档，并验证至少一个成功和一个失败场景。
