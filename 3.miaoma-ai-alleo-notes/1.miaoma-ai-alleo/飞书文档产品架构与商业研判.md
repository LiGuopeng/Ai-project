# 飞书文档类产品：架构与商业研判

## 一、先做什么：机会与定位

### 目标问题
- 团队知识分散在文档、群聊、表格与个人笔记中
- 协作、权限、版本、搜索与知识复用彼此割裂
- 现有工具要么重、要么难定制、要么本地优先能力不足

### 首要用户
- 10–200 人的产品、研发、运营与专业服务团队
- 需要知识沉淀、多人协作、审批留痕的组织
- 对私有化、权限和数据可控有要求的企业

### 产品承诺
- 一份内容，多种协作：文档、评论、任务、数据库视图与嵌入
- 一套权限与版本：可追溯、可恢复、可审计
- 先 Web SaaS，逐步覆盖离线与桌面端

### 关键验证
- 3–5 个真实团队访谈与试用
- 2 周内做出可用编辑器并观察留存
- 用“每周活跃文档数、协作者数、搜索成功率”判断价值

## 二、用户与核心场景

### 高频场景
- 项目空间：需求、方案、会议纪要、复盘
- 团队知识库：规范、FAQ、 onboarding、流程
- 客户交付：模板、批注、审批、导出
- 管理与审计：权限、修订历史、回收站、操作日志

### 关键体验
- 块级编辑、拖拽排序、Slash 菜单、页面嵌套
- @提及、评论线程、任务块、页面引用
- 实时光标与选区、离线草稿、版本对比
- 全文检索、标签、收藏、分享链接

## 三、产品架构：从内容到基础设施

### 领域模型
- Tenant → Workspace → Space/Collection → Document
- Document：标题、父级、排序、状态、所有者、权限
- BlockTree：稳定 Block ID、类型、属性、children、inline marks
- Comment/Thread：绑定 Block ID + range 或结构化锚点
- Revision/Snapshot：CRDT 更新或压缩快照
- Attachment/Embed、ShareLink、SearchIndex、Notification、AuditEvent

### 编辑器层
- 推荐 MVP：React + Vite + BlockNote
- 长期定制：Tiptap + ProseMirror，自建 BlockNode 与产品 UI
- 企业能力参考：CKEditor 5 的模型/视图转换、评论、修订与导出
- 规则：内部 BlockTree 是领域协议，不能把编辑器 JSON 当公共 API

### 协作与一致性
- Editor transaction → Y.Doc / 共享类型 → WebSocket
- Hocuspocus 或自建协作服务处理房间、presence、冲突合并
- Redis 做 presence、房间路由与短期缓存
- 明确租户隔离、离线更新保留、垃圾回收、历史回放与鉴权时机

### API 与数据层
- API：NestJS/TypeScript 或 Koa
- Metadata DB：PostgreSQL + Prisma/Drizzle
- Cache/Queue：Redis + BullMQ
- Object Storage：S3 兼容存储，保存图片、附件、导出包、快照
- Search：PostgreSQL FTS 起步，规模化后 OpenSearch
- Worker：导入导出、缩略图、AI 摘要、索引、病毒扫描

### 客户端与工程
- Web：React，按场景和路由拆包
- 桌面端：Electron；本地优先可参考 AFFiNE/BlockSuite
- 跨平台优先时参考 AppFlowy 的 Flutter + Rust 分层
- 测试：编辑器快照、协作冲突、导入导出往返、权限与审计

## 四、MVP → V1 → V2 路线

### MVP：2–4 周可用
- 文档树、标题/段落/列表/引用/代码/图片
- Block ID、拖拽排序、Slash 菜单、Markdown/HTML 导入导出
- 单文档实时协作、光标/选区、基础评论
- 工作区成员、文档级 ACL、分享链接、回收站
- PostgreSQL 元数据、S3 附件、Redis 队列、基础全文检索

### V1：形成团队习惯
- 页面嵌套、双向链接、@提及、任务块、表格/数据库视图
- 修订历史、版本对比、评论线程、通知、审计日志
- 权限继承、群组、访客、组织级空间与模板
- 导出 PDF/Word/Markdown；导入 Notion/飞书/Word

### V2：形成差异化
- 离线编辑、本地优先同步、跨端一致性
- 批注、文档锁定、受限编辑、审批流
- AI 摘要、问答、语义搜索、引用溯源、自动化工作流
- Electron 或 Flutter 桌面端

## 五、技术选型决策

### 编辑器决策
- 2–4 周交付：BlockNote，默认 UI 与块交互节省开发量
- 长期自研与强定制：Tiptap，Headless + 扩展模型可控性高
- 企业级评论/修订/导出：CKEditor 5，先评估许可与云服务边界

### 产品参考仓库
- AFFiNE：文档 + 画布、本地优先、BlockSuite、AI
- AppFlowy：Flutter + Rust、跨平台、本地数据库与协作域模型
- Outline：知识库 SaaS 骨架、权限、认证、队列、搜索、ProseMirror
- Etherpad：作者归属、逐次修订、时间轴与审计透明度

### 许可证与依赖
- Tiptap 核心 MIT；部分 Pro 扩展与云服务商业化
- BlockNote 主体 MPL-2.0，xl-* 包 GPL-3.0
- AppFlowy AGPL-3.0；Outline BSL 1.1；CKEditor 5 GPL 或商业许可
- 商业发布前建立 SBOM、逐包审计许可证与兼容矩阵

## 六、商业研判：值不值得做、怎么赚钱

### 竞争格局
- 飞书/Notion：体验成熟、生态强，但定制与数据控制有限
- Outline：团队知识库骨架完整，适合自部署与二次开发
- AFFiNE/AppFlowy：本地优先与跨平台有特色，但工程复杂
- 纯编辑器项目：解决内核，不解决权限、搜索、协作与商业闭环

### 差异化假设
- 面向中文团队的“可控知识协作”：权限、审计、私有化、导入迁移
- 文档 + 任务 + 数据库视图的轻量融合，不追求全功能复制
- 以 BlockTree 为统一内容协议，降低导入导出与 AI 应用成本

### 付费路径
- SaaS：按成员/工作区订阅，免费版限制空间与历史容量
- 企业版：SSO、审计、权限继承、私有化、SLA、合规支持
- 增值服务：迁移、模板、行业插件、AI 用量、存储与导出额度
- 早期避免依赖广告，优先验证付费团队的留存与扩容

### 获客与验证
- 先找 3 个垂直行业设计伙伴：研发团队、交付团队、咨询/培训团队
- 用迁移工具切入：Notion/飞书/Word/Markdown 一键导入
- 通过模板、案例、开源核心或社区建立自然流量
- 关键指标：激活率、周活跃工作区、协作者渗透率、搜索成功率、付费转化、净收入留存

### 护城河
- 内容协议与迁移能力：越用越难迁移，形成数据网络效应
- 权限/审计/审批等企业流程深度
- 行业模板、插件生态与组织知识图谱
- 协作性能、离线一致性与大文档体验

## 七、风险、决策与讨论清单

### 主要风险
- 数据模型锁定过早：编辑器内部 JSON 不能直接当公共 API
- 协作权限遗漏：建连、入房间、广播、历史读取都要鉴权
- 大文档性能：虚拟化、懒加载、增量快照需前置设计
- 导入导出丢失字段：必须有快照测试与差异报告
- CRDT 历史、可见版本、审计日志、回收站语义混淆
- 许可证与第三方升级可能影响商业发布和协作协议

### 合伙人需要拍板
- 先做 Web SaaS，还是第一天就做本地优先/桌面端
- 编辑器选 BlockNote 起步，还是直接 Tiptap 自建块层
- 目标客户优先团队协作，还是私有化/合规企业
- 免费增长优先，还是从设计伙伴和企业合同开始
- AI 是核心卖点，还是在内容与权限基础设施稳定后切入

### 90 天行动计划
- 0–2 周：访谈、需求冻结、许可证清单、信息架构与 BlockTree 协议
- 3–6 周：MVP 编辑器、文档树、协作、ACL、搜索、导入导出
- 7–10 周：3 个设计伙伴试用，采集指标与故障样本
- 11–12 周：商业报价、产品路线复盘、决定 V1 投入与技术路线

## 八、当前建议结论

### 推荐起步架构
- React + Vite
- BlockNote（或 Tiptap/ProseMirror）
- Yjs + Hocuspocus/WebSocket
- NestJS/Koa + PostgreSQL + Redis + S3
- PostgreSQL FTS 起步，Worker 处理导入导出、索引与 AI

### 推荐商业切入
- 先服务 10–200 人、有知识沉淀与权限需求的中文团队
- 用“可控知识协作 + 迁移工具 + 企业权限审计”建立差异化
- 先以设计伙伴验证留存和付费，再扩展离线、桌面端与 AI
