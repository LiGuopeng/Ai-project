# 需求分析

## 1. 问题定义

项目型团队的资料分散在文档、群聊、会议、网盘和表格中。信息进入系统后，仍然需要人工整理、确认来源和复制到任务工具。产品要把这些动作收拢在文档上下文里，并让 AI 产出的内容可追溯、可确认、可执行。

## 2. 产品边界

### 做什么

- 文档和知识库
- 块编辑与基础协作
- 基于当前上下文的 AI 操作
- 任务、评论、通知和版本
- 工作区成员与文档级权限
- 基础搜索、导入导出和附件

### 暂不做什么

- 全量即时通讯和外部客户管理
- 复杂人事、财务和制造流程
- 多维表格的完整数据库能力
- 多端离线优先同步
- 复杂行业模板市场
- 自研大模型训练

## 3. 目标与非目标

### 业务目标

在 12 至 16 周内完成可试点版本，支持 12 个团队同时使用，并验证团队是否能在一个工作周期内完成“资料进入、文档整理、AI 生成、任务执行、周报复用”。

### 产品目标

1. 新用户 10 分钟内完成一次有保存结果的 AI 任务。
2. 用户能从文档、任务和评论回到同一份上下文。
3. 管理员能在 5 分钟内完成成员、空间和文档权限配置。
4. AI 结果默认带引用，用户可以一键采纳、编辑或转成任务。

### 非目标

第一版不追求覆盖所有办公软件能力，也不以注册量、模型调用量或文档创建量作为主要成功标准。

## 4. 需求优先级

优先级采用 P0、P1、P2。P0 是试点必需，P1 用于提高复用和留存，P2 进入后续验证。

| 模块 | P0 | P1 | P2 |
|---|---|---|---|
| 文档 | 工作区、文档树、标题、段落、列表、引用、代码、图片、拖拽排序 | 页面嵌套、模板、双向链接、表格 | 数据库视图、白板 |
| AI | 摘要、改写、提取任务、周报、带引用问答 | 自定义指令、批量处理、会议转写导入 | 自动化 Agent、跨应用执行 |
| 协作 | 实时编辑、presence、评论、@提及 | 评论线程、决策标记、任务状态 | 修订建议、多人批注 |
| 权限 | 工作区成员、空间和文档 ACL、分享链接 | 群组、权限继承、访客 | SSO、SCIM、私有化 |
| 搜索 | 标题和全文搜索、权限过滤 | 标签、最近访问、搜索高亮 | 语义搜索、跨系统搜索 |
| 版本 | 自动保存、最近版本、恢复 | 版本对比、命名版本 | 审计时间轴和细粒度回放 |
| 任务 | 从 AI 结果创建任务、负责人、截止日期、状态 | 项目任务列表、提醒 | 自动排期、依赖关系 |
| 导入导出 | Markdown、HTML、DOCX 基础导入导出 | 飞书/Notion 导入 | 多系统双向同步 |

## 5. 核心用户流程

### 流程 A 进入项目并建立文档

用户注册或加入工作区，创建空间，选择项目模板，邀请成员，打开文档并开始编辑。系统自动保存，文档在树中保持稳定位置。

### 流程 B 文档到 AI 结果

用户选中一段文字或打开 AI 工作台，选择摘要、改写、提取任务、生成周报或询问文档。系统显示生成状态、结果和引用。用户可以采纳、插入正文、复制、继续追问或转成任务。

### 流程 C 会议到任务

用户粘贴会议记录或导入转写文本，系统提取决策、任务、负责人、截止日期和待确认项。用户逐条确认后，任务进入项目列表，原文保留来源链接。

### 流程 D 协作与版本

成员同时编辑，看到彼此的光标和在线状态。用户在选区发表评论并@成员。系统自动保存版本，用户可以查看最近版本、恢复版本，并保留审计事件。

## 6. 领域模型

```text
Tenant
 └─ Workspace
     ├─ Member / Group / Role
     ├─ Space
     │   └─ Document
     │       ├─ BlockTree
     │       ├─ Comment / Thread
     │       ├─ Task
     │       ├─ Revision
     │       └─ Attachment
     ├─ ShareLink
     ├─ SearchIndex
     ├─ Notification
     └─ AuditEvent
```

### 内容原则

- `Document` 保存标题、父级、排序、状态、所有者和权限等元数据。
- `BlockTree` 保存版本化的规范 JSON，不以 HTML 作为唯一真相。
- 每个 Block 有稳定 ID、类型、属性和 children。
- 评论和任务引用 Block ID 与结构化范围，避免绑定 DOM 偏移量。
- AI 结果保存输入范围、模型、提示版本、引用和用户采纳动作。

## 7. 权限模型

第一版采用工作区、空间、文档三级边界。角色包括工作区管理员、成员、访客。文档权限包括查看、评论、编辑、管理。权限检查发生在页面加载、搜索、AI 检索、WebSocket 入房、附件下载和分享链接访问等所有入口。

权限继承默认打开，子文档可以显式收紧。分享链接默认关闭，开启后需要设置查看或评论权限、有效期和撤销状态。管理员操作、分享、导出、恢复版本和删除文档进入审计日志。

## 8. 技术与体验约束

### 编辑器

MVP 优先用 BlockNote 获得块编辑、拖拽、Slash 菜单和 React UI。自定义块和复杂评论通过 Tiptap/ProseMirror 扩展补齐。建立独立的文档协议版本，避免产品 API 被编辑器内部结构锁死。

### 协作

使用 Yjs 文档承载实时更新，Hocuspocus 或兼容 WebSocket 服务负责房间与同步。元数据、权限、评论、任务和审计仍由 API 与 PostgreSQL 管理。权限变更不能只依赖 CRDT 广播。

### 性能目标

- 文档首屏可编辑时间 P95 小于 2.5 秒。
- 常规编辑操作本地响应 P95 小于 100 毫秒。
- AI 首字响应 P95 小于 5 秒，超时显示可继续等待状态。
- 搜索结果 P95 小于 1.5 秒。
- 试点规模下单文档支持 5000 个块，长文档采用懒加载和虚拟化。

## 9. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 事实错误 | 用户不信任，出现错误执行 | 强制引用、显示来源、支持逐条采纳和反馈 |
| 权限漏读 | 数据泄露 | 检索前做 ACL 过滤，建立越权测试集和审计 |
| 编辑器数据被锁定 | 后期迁移成本高 | 版本化领域协议，建立导入导出快照测试 |
| 实时协作复杂 | 丢失更新、状态不一致 | 先限定单文档协作，明确 CRDT 与业务数据边界 |
| 大文档性能下降 | 编辑体验变差 | 分块、虚拟化、增量快照和附件异步处理 |
| 范围膨胀 | 试点延期 | 以核心闭环为发布门槛，复杂 OA 进入候选池 |
| 许可证边界 | 商业发布受限 | 逐包建立 SBOM，发布前完成许可证复核 |

## 10. 试点指标

| 指标 | 目标 |
|---|---:|
| 首次价值时间 | ≤ 10 分钟 |
| 周活跃使用 AI 动作的成员占比 | ≥ 60% |
| AI 结果被接受、编辑后保存的比例 | ≥ 40% |
| 纪要转任务并完成至少一步的比例 | ≥ 30% |
| 一周内被二次引用的文档占比 | ≥ 25% |
| 第 4 周团队留存 | ≥ 50% |
| 试点后愿意签年付的团队 | ≥ 25% |

## 11. 12 至 16 周交付节奏

| 阶段 | 周期 | 结果 |
|---|---:|---|
| 方案冻结 | 第 1 周 | 文档协议、权限矩阵、原型和埋点字典 |
| 基础空间 | 第 2 至 4 周 | 登录、工作区、空间、文档树、基础编辑 |
| 协作与权限 | 第 5 至 7 周 | 实时编辑、成员、ACL、评论、附件 |
| AI 闭环 | 第 8 至 10 周 | 摘要、改写、任务、周报、引用和反馈 |
| 搜索与版本 | 第 11 至 12 周 | 全文搜索、自动保存、版本恢复、审计 |
| 试点准备 | 第 13 至 14 周 | 导入导出、监控、数据清理、帮助中心 |
| 试点迭代 | 第 15 至 16 周 | 12 个团队试用、访谈、指标复盘和范围决策 |

## 12. 需要产品负责人拍板的事项

1. 首批试点是否聚焦一种行业，还是维持四类团队的横向验证。
2. 是否把会议转写作为首版输入，还是先支持粘贴文本与文件导入。
3. AI 使用是否计量收费，还是在试点阶段统一包含。
4. 是否首版接入某一个外部平台，还是先把导入导出做稳定。
5. 是否接受云端存储作为默认方案，私有化放到商业验证阶段。
