# AI 文档工作空间产品方案

这组文档把现有的编辑器调研和 AI 文档型 OA 市场调研，整理成一条可以继续执行的产品流程。

## 产品暂定定义

**产品名**  AI 文档工作空间

**一句话定位**  面向 20 至 200 人项目型团队，用文档和知识库承接会议、文件与协作信息，再把内容转成可执行任务和轻量流程。

**首批目标用户**  专业服务、营销与内容、电商运营、软件交付、培训咨询团队。

**首个切入场景**  会议或项目资料进入空间后，团队可以快速整理成文档，使用 AI 生成摘要、任务和周报，并且每条结论都能回到原文证据。

**技术路线建议**  Web 端采用 React + Vite，编辑器优先评估 BlockNote，复杂能力下沉到 Tiptap/ProseMirror；协作采用 Yjs + Hocuspocus/WebSocket；元数据使用 PostgreSQL，附件使用 S3 兼容对象存储，异步任务使用 Redis 队列。

## 当前阶段的决策

1. 先做文档、知识库、上下文 AI、轻量任务和基础协作。
2. 暂不做完整通讯录、复杂审批、财务、人事、CRM 和行业流程市场。
3. AI 输出必须带引用，并且可以直接转成任务、评论或文档内容。
4. 编辑器内部 JSON 不直接作为公共 API，产品层使用版本化的文档协议。
5. 先做 Web SaaS，离线优先、桌面端和本地部署进入后续验证。

## 使用顺序

先用用户研究文档确定访谈对象和验证假设，再用需求分析文档做范围评审。范围冻结后，以 PRD 作为研发和测试依据，再用原型文件开展可用性测试。每一轮测试的结果回写到需求分析中的决策日志。
