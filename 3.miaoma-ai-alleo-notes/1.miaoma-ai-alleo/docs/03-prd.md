# AI 文档工作空间 PRD

## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 产品 | AI 文档工作空间 |
| 文档版本 | 0.1 |
| 目标版本 | MVP 试点版 |
| 目标用户 | 20 至 200 人项目型、知识密集型团队 |
| 依据 | 用户研究与需求分析文档、两份现有调研材料 |
| 状态 | 待产品负责人确认范围后进入设计与开发 |

## 1. 产品目标

用户可以在一个工作空间中创建和协作文档，使用当前文档与项目上下文完成 AI 总结、改写、任务提取和周报生成。每个 AI 结果都能回到来源，用户确认后可以直接写入文档或转成任务。

## 2. 核心原则

1. 文档上下文优先，AI 动作出现在用户正在工作的地方。
2. 结果可追溯，所有事实性结论显示来源。
3. 人工确认后执行，AI 负责生成，用户决定是否采纳。
4. 权限先于检索，用户能看到的内容才允许进入 AI 上下文。
5. 内容和产品元数据分开，保证未来迁移和多端扩展。

## 3. 信息架构

```text
工作区
 ├─ 首页
 │   ├─ 最近访问
 │   ├─ 我的任务
 │   └─ 快速创建
 ├─ 空间
 │   ├─ 文档树
 │   ├─ 任务
 │   └─ 成员与权限
 ├─ AI 工作台
 │   ├─ 当前文档

     ├─ 分享链接
     ├─ 审计日志
     └─ 导入导出
```

## 4. 功能需求

### DOC-001 工作区与空间

用户可以创建工作区、创建空间、命名空间、设置空间描述并邀请成员。空间用于隔离项目或知识主题。

验收标准

- 创建工作区后自动进入首页并生成默认空间。
- 成员邀请支持邮箱或邀请链接，邀请状态可查看和撤销。
- 空间列表显示名称、成员数、最近更新时间和权限状态。

### DOC-002 文档树

用户可以创建、重命名、移动、复制、归档和恢复文档。文档树支持至少两级嵌套，拖拽后即时更新排序。

验收标准

- 移动文档前显示目标位置，移动失败时保留原位置。
- 归档文档不出现在默认树中，但可以在回收站恢复。
- 文档有稳定 URL，移动后 URL 不变。

### EDIT-001 块编辑器

编辑器支持标题、段落、待办、编号列表、无序列表、引用、代码块、分割线、图片和链接。支持 Slash 菜单、块拖拽、快捷键、Markdown 粘贴和自动保存。

验收标准

- 新文档打开后 2.5 秒内进入可编辑状态。
- 输入、撤销、重做、复制粘贴和块移动可正常工作。
- 每个块有稳定 ID，保存后刷新内容不丢失。
- 图片上传失败时显示原因，正文保留可重试状态。

### EDIT-002 模板

首版提供项目周报、会议纪要、方案评审和知识卡片四个模板。模板只负责创建初始文档结构，后续内容可自由编辑。

### AI-001 上下文 AI 动作

用户可以在选中文字后调用摘要、改写、扩写、翻译、提取任务，也可以从文档顶部打开 AI 工作台。AI 工作台支持基于当前文档或整个空间的问答。

验收标准

- AI 操作显示输入范围、进行中状态、取消入口和失败重试。
- 生成结果可插入文档、复制、继续追问、重新生成或反馈。
- 当前文档问答默认只检索用户有权限的内容。
- 结果显示生成时间、模型标识和引用列表。

### AI-002 引用与证据

AI 输出中的事实性结论以引用标记关联到文档块、附件页码或任务记录。点击引用后，页面滚动到原文并高亮范围。

验收标准

- 引用至少包含文档标题、块位置和可打开链接。
- 原文被删除或权限变化后，引用显示失效原因。
- 用户可以对单条引用标记“有帮助”或“来源不准确”。

### AI-003 会议到任务

用户粘贴会议记录或导入文本后，AI 识别决策、任务、负责人、截止日期和待确认项。用户逐条勾选后创建任务。

验收标准

- AI 不得在用户未确认时自动创建任务或发送通知。
- 缺少负责人或截止日期的任务显示待确认状态。
- 每个任务保存来源文档和原文范围。

### TASK-001 任务

任务字段包括标题、描述、负责人、截止日期、状态、优先级、来源文档和创建人。状态包括待处理、进行中、已完成、已取消。

验收标准

- 任务可以从文档、AI 结果或任务列表创建。
- 任务完成后保留完成时间和完成者。
- 文档中的任务块与任务列表保持双向更新。

### COL-001 实时协作

多人打开同一文档时显示在线成员、光标颜色和选区。文本编辑与块操作通过实时协议同步。

验收标准

- 两名用户同时编辑不同段落时，双方最终内容一致。
- 网络短暂断开后自动重连，期间本地编辑不被覆盖。
- 无文档编辑权限的用户不能通过 WebSocket 写入更新。

### COM-001 评论与提及

用户可以选中文字发表评论、回复、解决评论和@成员。评论侧栏按文档位置和时间展示。

验收标准

- 评论锚点与块 ID 关联，文档轻微修改后仍能定位。
- 解决评论后默认收起，历史中可查看。
- 被@成员收到站内通知，通知链接能打开对应范围。

### VER-001 版本与恢复

系统自动保存版本。用户可以查看最近版本、版本创建时间、创建人和恢复入口。恢复前需要二次确认。

验收标准

- 恢复版本会创建一个新版本，不覆盖历史版本。
- 版本页面显示内容摘要和差异范围。
- 管理员可以在审计日志中看到恢复动作。

### AUTH-001 成员与权限

支持工作区管理员、成员、访客三个角色，以及空间和文档级查看、评论、编辑、管理权限。

验收标准

- 页面、API、搜索、AI 检索、附件下载和协作房间使用同一权限策略。
- 移除成员后，已有会话在下一次请求时失效。
- 分享链接可以设置权限、有效期和撤销状态。

### SEA-001 搜索

支持标题和正文全文搜索，结果按权限过滤，并展示匹配片段、文档位置和最近更新时间。

验收标准

- 无权限文档不出现在结果、联想和 AI 检索中。
- 用户点击结果后定位到匹配文本。
- 索引失败进入重试队列，不阻塞文档保存。

### FILE-001 附件

支持图片和常见文档附件。附件进入对象存储，文档中保存元数据和引用关系。

验收标准

- 上传过程显示进度、大小限制和失败原因。
- 下载链接经过权限校验并具有短时有效期。
- 删除文档不会立即删除仍被其他文档引用的附件。

### IMP-001 导入导出

首版支持 Markdown、HTML、DOCX 基础导入导出。导入失败时给出字段丢失和格式降级报告。

验收标准

- 导入前显示文件名、预计文档数量和目标空间。
- 导出内容保留标题层级、列表、链接、图片和代码块。
- 导入导出建立快照测试，发现字段丢失时阻止静默通过。

### AUD-001 审计

记录登录、邀请、权限变更、分享、导出、AI 检索、版本恢复、删除和管理员操作。普通成员只能查看自己有权限范围内的事件。

## 5. AI 交互规范

AI 面板包含上下文范围、动作选择、输入框、结果区、引用区和反馈区。默认上下文为当前文档，用户可以显式加入当前空间或指定文档。系统不把全工作区作为无提示的默认上下文。

结果区至少提供采纳、插入文档、转为任务、复制、重试、反馈和查看引用。涉及任务、权限、分享和删除的操作，必须经过用户确认。

## 6. 数据结构示例

```json
{
  "documentId": "doc_xxx",
  "protocolVersion": "1.0",
  "title": "项目周报",
  "blocks": [
    {
      "id": "block_xxx",
      "type": "heading",
      "props": { "level": 1 },
      "content": [{ "text": "本周进展", "marks": [] }],
      "children": []
    }
  ],
  "updatedAt": "2026-09-19T09:00:00Z"
}
```

AI 结果至少保存 `requestId`、`documentId`、`scope`、`action`、`model`、`promptVersion`、`citations`、`result`、`status` 和 `createdBy`。敏感原文不写入普通应用日志。

## 7. 页面状态

| 页面 | 加载中 | 空状态 | 错误状态 | 无权限状态 |
|---|---|---|---|---|
| 首页 | 骨架屏 | 创建空间提示 | 重试按钮 | 联系管理员 |
| 文档树 | 局部骨架 | 创建第一篇文档 | 恢复上次状态 | 隐藏无权限节点 |
| 编辑器 | 编辑器骨架 | 模板或空白文档 | 本地草稿与重试 | 只读模式 |
| AI 面板 | 进度状态 | 选择一个动作 | 重试与反馈 | 无可用上下文 |
| 搜索 | 输入框保留 | 无结果建议 | 重试 | 只返回有权限内容 |
| 版本 | 时间线骨架 | 暂无历史版本 | 重试 | 无管理权限则隐藏恢复 |

## 8. 事件埋点

核心事件包括 `workspace_created`、`document_created`、`document_opened`、`editor_first_input`、`ai_action_started`、`ai_result_saved`、`citation_opened`、`task_created_from_ai`、`task_completed`、`comment_created`、`revision_restored`、`search_used`、`import_completed` 和 `share_link_created`。

事件统一包含工作区、空间、文档、用户、来源页面、客户端版本和时间。AI 事件增加动作类型、输入范围、结果状态、引用数量和用户反馈，不记录原文全文。

## 9. 非功能需求

- 安全  所有对象访问进行租户和资源级鉴权，敏感操作有审计，附件链接短时有效。
- 可靠性  文档保存失败不覆盖本地编辑内容，协作连接异常有重连和状态提示。
- 可观测性  记录 API、协作连接、AI 请求、队列、索引和导入导出的成功率与耗时。
- 可访问性  关键操作支持键盘，颜色不是唯一状态表达，焦点顺序可预测。
- 可迁移性  文档协议有版本号，导入导出有快照测试，避免依赖单一编辑器内部结构。
- 成本  AI 模型、音频转写、对象存储和检索成本按工作区统计，便于试点后的商业测算。

## 10. 发布门槛

### 功能门槛

P0 功能全部通过验收，至少完成一条从创建空间到文档、AI 结果、任务、评论和版本恢复的完整流程。

### 质量门槛

通过权限越权测试、协作一致性测试、导入导出快照测试、核心浏览器兼容测试、长文档性能测试和附件权限测试。

### 试点门槛

至少 3 个团队完成一周真实使用，数据不出现严重权限问题，AI 结果保存率达到 40% 的试点目标，才扩大到 12 个团队。
