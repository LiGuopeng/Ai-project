# 可沉淀为 Skill 的工作节点

这些节点具有输入稳定、步骤可复用、输出可检查的特点，适合后续独立沉淀为 Skill。当前先记录边界，不立即创建新的 Skill。

## 1. 调研材料转产品机会

输入是市场调研、竞品调研和用户材料。输出是目标用户、问题定义、机会区间、非目标、验证假设和指标。检查点是每个判断都能回到来源，事实、推断和未知分开。

## 2. 用户研究计划生成

输入是产品方向和已知约束。输出是用户分层、JTBD、访谈提纲、招募条件、研究任务和通过线。检查点是问题围绕真实行为，避免只问“你喜不喜欢”。

## 3. 需求优先级评审

输入是用户问题、商业目标、技术约束和候选功能。输出是 P0、P1、P2 需求表、非目标、版本边界和决策日志。检查点是每个 P0 都服务核心闭环，并有验收条件。

## 4. 文档类产品 PRD 生成

输入是需求分析和技术路线。输出是功能编号、用户故事、流程、页面状态、权限、数据结构、非功能要求、埋点和发布门槛。检查点是功能能被设计、开发和测试分别使用。

## 5. 原型评审清单

输入是 PRD 和页面原型。输出是页面清单、关键路径、异常状态、可访问性要求和可用性测试任务。检查点是空、错、无权限、加载中、网络断开等状态都有位置。

## 6. AI 功能证据链设计

输入是 AI 动作、上下文范围和权限模型。输出是引用结构、确认点、反馈事件、越权测试和模型成本指标。检查点是 AI 结果能回到来源，执行型动作必须经用户确认。

## 7. 适合制作 Skill 的共性要求

- 明确触发条件和不适用范围。
- 规定输入文件、上下文和缺失材料的处理方式。
- 使用固定输出结构，便于评审和自动检查。
- 保留来源、假设、决策和未知项。
- 设置质量门槛，例如权限测试、字段完整性、验收标准和指标口径。

## 8. 建议的沉淀顺序

先沉淀“需求优先级评审”和“文档类产品 PRD 生成”，这两个节点最稳定，也最容易复用于不同产品。用户访谈积累三到五轮后，再沉淀“用户研究计划生成”。AI 证据链设计应在实际模型和权限数据跑通后再固定模板。
