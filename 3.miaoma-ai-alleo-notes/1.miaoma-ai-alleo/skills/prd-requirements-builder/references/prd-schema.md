# PRD 标准结构

生成 PRD 时按以下顺序组织。项目可增加章节，但不能删除“功能需求”“异常流程矩阵”和“不在本期范围”。

## 1. 文档信息

包含产品名、版本、负责人、状态、目标版本、来源材料和更新时间。

## 2. 背景与问题

说明用户、当前做法、具体代价、机会和事实边界。把已经验证的事实、推断和假设分开。

## 3. 目标与成功指标

列出业务目标、产品目标、核心指标、目标值、统计口径和观察周期。没有数据基础的指标标注为待验证假设。

## 4. 用户与使用场景

包含目标用户、角色差异、JTBD、核心旅程和关键使用场景。每个场景要能连接到后续需求 ID。

## 5. 产品范围

明确产品定位、核心闭环、本期范围、依赖条件和“不在本期范围”。范围外清单至少有排除原因和后续触发条件。

## 6. 用户故事

采用“作为某角色，我希望完成某动作，以便获得某结果”的格式。用户故事必须链接到功能需求 ID。

## 7. 功能需求

每个需求使用三级标题和唯一 ID，例如 `### AI-001 上下文摘要`。每个需求至少包含以下字段。

```markdown
### AI-001 上下文摘要

优先级  P0

用户故事  作为项目负责人，我希望根据当前文档生成摘要，以便快速了解进展。

前置条件  用户有文档查看权限，文档正文不为空。

主流程

1. 用户打开文档并点击“生成摘要”。
2. 系统以当前文档作为默认上下文。
3. 系统展示生成状态、结果和引用。
4. 用户可以采纳、编辑、复制或重试。

异常流程

- 文档为空时显示引导，不发起模型请求。
- 模型超时时保留当前页面，允许重试。
- 引用为空时标记结果需要人工确认，不允许直接创建任务。

验收标准

- Given 用户有文档查看权限且文档有正文，When 点击“生成摘要”，Then 在 5 秒内显示结果状态，并展示至少一条可打开的引用或明确的无引用状态。
- Given 模型请求超时，When 超过超时阈值，Then 页面保留当前文档内容，显示失败原因，并提供重试入口。

数据与埋点  记录动作类型、上下文范围、结果状态、引用数量和用户采纳动作，不记录原文全文。

依赖与开放问题  依赖检索服务；模型路由待确认。
```

## 8. 异常流程矩阵

至少包含以下列。

| 场景 | 是否适用 | 触发条件 | 用户反馈 | 数据处理 | 验收标准 |
|---|---|---|---|---|---|
| 空状态 | 是/否 | 何时发生 | 页面提示 | 是否保留 | Given / When / Then |
| 加载失败 | 是/否 | 何时发生 | 错误信息与重试 | 是否重试 | Given / When / Then |
| 权限不足 | 是/否 | 何时发生 | 无权限提示 | 是否隐藏数据 | Given / When / Then |
| 网络断开 | 是/否 | 何时发生 | 离线或重连提示 | 草稿是否保留 | Given / When / Then |
| 输入校验 | 是/否 | 何时发生 | 字段级提示 | 是否阻止提交 | Given / When / Then |
| 重复提交 | 是/否 | 何时发生 | 去重提示 | 是否幂等 | Given / When / Then |
| 并发冲突 | 是/否 | 何时发生 | 冲突提示 | 合并或回滚 | Given / When / Then |
| 超时重试 | 是/否 | 何时发生 | 进度和重试 | 是否幂等 | Given / When / Then |
| 删除恢复 | 是/否 | 何时发生 | 二次确认 | 回收或恢复 | Given / When / Then |
| 导入导出 | 是/否 | 何时发生 | 字段丢失报告 | 是否生成报告 | Given / When / Then |
| 通知失败 | 是/否 | 何时发生 | 状态提示 | 是否补发 | Given / When / Then |
| AI 错误或无引用 | 是/否 | 何时发生 | 风险提示 | 是否禁止执行 | Given / When / Then |

## 9. 页面与交互状态

至少说明加载中、成功、空状态、错误、无权限、只读、网络断开和确认弹窗。页面状态要关联到功能需求 ID。

## 10. 数据、权限与接口

说明核心实体、字段、状态机、权限检查位置、接口输入输出、幂等策略、审计和敏感数据处理。

## 11. 非功能需求

按产品实际情况写性能、可用性、安全、可访问性、兼容性、可观测性、成本和可迁移性。每项尽量给出可测量阈值。

## 12. 埋点与指标

列出事件名、触发时机、关键属性、统计口径、目标值和数据保留策略。避免把原文全文或敏感数据写进普通日志。

## 13. 测试与发布门槛

包括功能测试、异常测试、权限越权测试、兼容性测试、性能测试、数据迁移测试和灰度标准。发布门槛要能判断“可以发布”或“必须回退”。

## 14. 待确认决策

列出会影响范围、成本、架构或上线时间的问题，并写明决策人、截止时间和默认方案。
