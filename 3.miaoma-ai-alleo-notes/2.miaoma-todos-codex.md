# Miaoma Todo 产品方案评审稿 v0.1

这篇先按“能拿来评审产品方向”的标准来写。内容覆盖产品定位、竞品判断、用户群体、功能范围、PRD、端设计、付费规则、技术架构、测试计划和发布方案。

当前工作区还没有落盘任何代码或文档，以下内容属于第一版方案草稿。

---

## 一、产品定位

产品暂定名为 Miaoma Todo。

它面向个人用户、家庭用户和小型团队，帮助用户完成四件事：

- 快速记录想法和待办
- 把任务安排到合适的时间
- 在执行过程中保持专注
- 在多个设备之间可靠同步

产品的核心体验应当集中在一条完整的日常工作流程上。

用户打开应用之后，可以迅速查看今天要完成的事情，随手增加任务，调整时间，进入专注状态，完成之后得到明确反馈。

产品不把自己做成复杂的企业项目管理工具，也不把所有生产力功能堆在首页。首期产品需要让用户在几十秒内完成一次任务记录，在一分钟内完成当天计划。

### 产品愿景

让任务记录、安排和执行变得简单、可靠、连续。

### 核心指标

首期建议关注以下指标：

| 指标 | 目标方向 |
| --- | --- |
| 新用户首次创建任务 | 30 秒内完成 |
| 新用户首次完成任务 | 注册后 10 分钟内完成 |
| 用户次日留存 | 关注用户是否愿意继续使用 |
| 每周活跃用户任务完成数 | 观察产品是否真正进入工作流 |
| 同步成功率 | 目标达到 99.9% 以上 |
| 提醒送达率 | 目标达到 99% 以上 |
| 用户从 Inbox 清空到 Today 的时间 | 持续缩短 |
| 免费用户转 Pro 比例 | 验证付费价值 |

## 二、竞品调研

本次主要参考 Things 3 和 TickTick 官方页面，也结合两类产品在市场上的使用方式进行判断。

### Things 3 的产品特点

Things 3 的核心价值在于清晰和克制。

它把任务组织成几个非常容易理解的区域：

- Inbox
- Today
- This Evening
- Upcoming
- Anytime
- Someday
- Areas
- Projects
- Tags
- Headings
- Checklists

它支持任务备注、标签、开始日期、截止日期、提醒、重复任务、Markdown、日历事件、Siri、Shortcuts、快速搜索和跨设备同步。

Things 3 的优势主要体现在以下方面：

- 信息结构简单
- 日常计划路径短
- 视觉干扰少
- Mac 端键盘效率高
- iPad 端对拖拽和多选支持较好
- 任务、项目、区域之间的关系清楚
- 任务详情足够丰富，但默认状态保持简洁

它的商业模式具有明显的 Apple 生态特征。

Things 3 按平台分别售卖 Mac、iPhone、iPad、Vision Pro 等版本，官网定价页面提示用户前往 App Store 查询本地区价格。它采用一次性购买逻辑，没有把核心功能绑定到持续订阅中。

Things 3 的不足也比较明显：

- 平台范围集中在 Apple 生态
- 团队协作能力较弱
- 共享、评论、权限和组织管理不是产品重点
- 习惯、番茄钟、倒计时和复杂日历能力有限
- 对中国本地服务和通知渠道支持较少

### TickTick 的产品特点

TickTick 的方向更宽。

除了任务本身，它还包含：

- 多种日历视图
- 习惯追踪
- 番茄钟
- 倒计时
- 清单和看板
- 任务时长
- 邮件提醒
- 主题
- 统计
- 小组件
- 多平台同步
- 团队共享
- 第三方集成

TickTick 官网当前显示，免费版包含以下限制：

- 9 个列表
- 每个列表 99 个任务
- 每天 1 个附件
- 每个任务 19 个清单项
- 2 个任务提醒
- 2 个成员
- 5 个习惯
- 5 个倒计时

Premium 版本当前官网价格显示为每年 49.99 美元，具体金额可能受到地区、平台和支付渠道影响。

Premium 增加的内容包括：

- 更高的列表和任务容量
- 多种日历视图
- 任务时长
- 邮件提醒
- 主题
- 更高的附件容量
- 更高的习惯和倒计时容量
- 高级统计
- 高级筛选
- 高级集成
- 更多团队和共享功能

TickTick 的优势是覆盖面大，适合希望把任务、日历、习惯、专注和提醒放在一个应用中的用户。

它的问题在于功能较多，长期使用之后，用户需要花时间理解产品结构。对于只想快速记一件事情的人来说，首页可能会显得偏复杂。

### 我们的产品机会

Miaoma Todo 可以采用以下产品方向：

| 竞品能力 | Miaoma Todo 的取舍 |
| --- | --- |
| Things 3 的任务结构 | 作为产品骨架 |
| Things 3 的快捷输入和清晰界面 | 作为桌面端重点 |
| TickTick 的跨平台能力 | 作为基础能力 |
| TickTick 的日历、习惯和专注 | 分阶段加入 |
| TickTick 的共享和团队功能 | 作为 Pro 与 Team 付费能力 |
| 中国用户的本地通知需求 | 增加微信、钉钉、飞书和邮件通知 |
| 中文输入习惯 | 增加中文自然语言日期识别 |
| 多端同步 | 采用离线可用和增量同步 |

产品第一阶段应该集中解决任务管理问题。日历、习惯、AI 和团队功能需要建立在稳定的任务模型之上。

## 三、用户群体

### 主要用户

#### 个人职场用户

他们每天有大量会议、工作事项和临时任务。

主要需求包括：

- 快速记录任务
- 按日期安排任务
- 处理重复工作
- 查看当天计划
- 在电脑和手机之间同步
- 通过提醒避免遗漏
- 用搜索找回旧任务

他们愿意为稳定同步、桌面效率、日历视图和跨设备体验付费。

#### 学生与备考用户

他们需要管理课程、作业、考试、复习计划和长期目标。

主要需求包括：

- 按课程或项目整理任务
- 设置截止日期
- 拆分阶段任务
- 设置重复提醒
- 查看一周安排
- 使用专注计时
- 记录完成情况

#### 自由职业者与创作者

他们同时处理多个客户、项目和个人目标。

主要需求包括：

- 按客户建立项目
- 记录合同、交付和回访
- 区分工作和生活
- 设置不同标签
- 管理周期性工作
- 使用看板和日历
- 跨设备操作

#### 家庭用户

家庭成员共同处理采购、旅行、装修、家务、孩子教育和账单。

主要需求包括：

- 创建共享清单
- 指派成员
- 评论和上传附件
- 设置到期提醒
- 查看谁完成了任务
- 共享购物或旅行计划

### 次要用户

- 小型工作室
- 5 到 20 人的小团队
- 需要个人任务和团队任务并行管理的管理者
- 需要中文任务和提醒能力的用户
- 从纸笔、备忘录或聊天工具迁移过来的用户

### 首期不重点服务的人群

首期不建议重点服务大型企业、复杂研发项目和多层级项目管理团队。

这些用户会要求：

- 复杂权限
- 审批流
- 甘特图
- 工时核算
- 预算管理
- 企业单点登录
- 组织架构同步
- 多级审计
- 合规报表

这些能力会显著增加系统复杂度，应当等个人和小团队产品稳定之后再评估。

## 四、产品原则

### 输入要快

用户不应该为了记录一条任务，先选择项目、标签、优先级和日期。

默认流程应当是：

1. 输入任务标题
2. 自动识别日期和时间
3. 需要时再补充项目、标签和提醒

### 计划要清楚

首页默认展示用户今天真正需要处理的任务。

过去的任务、未来的任务和暂时搁置的任务需要分开显示，避免所有内容挤在一个列表里。

### 详情逐步展开

任务默认只显示标题和完成状态。

备注、标签、清单、附件、提醒和时间等信息放到详情面板中。用户需要时再打开。

### 每个设备都能独立工作

手机没有网络时可以创建和完成任务。

桌面端需要支持键盘操作和快速捕获。

网页端需要适合浏览器长期使用。

恢复网络之后，各端通过同步机制合并变更。

### 数据始终属于用户

订阅到期之后保留用户已有数据。

降级到免费版之后，高级功能停止使用，历史任务、项目和备注继续保留。

## 五、产品信息架构

Miaoma Todo 的核心对象建议如下：

```text
用户 User
 └── 工作区 Workspace
      ├── 成员 Membership
      ├── 区域 Area
      │    └── 项目 Project
      │         └── 分组 Section
      │              └── 任务 Task
      │                   ├── 清单项 Checklist Item
      │                   ├── 标签 Tag
      │                   ├── 提醒 Reminder
      │                   ├── 评论 Comment
      │                   └── 附件 Attachment
      ├── 过滤器 Filter
      ├── 习惯 Habit
      ├── 日历 Calendar
      └── 订阅 Subscription
```

### 区域 Area

区域用于划分生活中的长期责任，例如：

- 工作
- 个人
- 家庭
- 学习
- 健康
- 财务

### 项目 Project

项目用于表示有明确结果的一组任务，例如：

- 发布一个课程
- 完成一次旅行计划
- 准备产品发布
- 搬家
- 完成考试复习

### 分组 Section

分组用于把项目拆成阶段或主题，例如：

- 前期准备
- 设计
- 开发
- 测试
- 发布

### 任务 Task

任务是用户可以执行或完成的最小工作单位。

### 清单 Checklist

清单用于拆解任务内部的小步骤。

例如“准备出差”可以包含：

- 订机票
- 准备身份证
- 整理电脑
- 打印文件
- 预订酒店

## 六、核心功能 PRD

## 6.1 账户与工作区

### 功能目标

用户注册后可以拥有个人工作区，也可以加入共享工作区。

### 支持方式

- 手机号注册
- 邮箱注册
- 微信登录
- Apple 登录
- Google 登录
- 密码登录
- 验证码登录

### 工作区类型

- 个人工作区
- 家庭工作区
- 团队工作区

### 成员角色

| 角色 | 权限 |
| --- | --- |
| Owner | 管理工作区、成员、订阅和全部内容 |
| Admin | 管理成员和共享内容 |
| Member | 创建、编辑和完成任务 |
| Viewer | 查看内容，不能编辑 |

---

## 6.2 Inbox 收集箱

Inbox 是所有临时任务的入口。

### 必须支持

- 快速创建任务
- 快捷键创建任务
- 移动端悬浮按钮创建任务
- 语音输入
- 中文自然语言日期识别
- 任务自动识别标签
- 任务自动识别时间
- 任务自动识别重复规则
- 离线创建
- 批量整理

### 示例

用户输入：

```text
周五下午三点提醒我给客户发报价单 #客户A
```

系统应该识别为：

- 标题：给客户发报价单
- 日期：本周五
- 时间：15:00
- 标签：客户A
- 提醒：15:00

识别结果需要在提交前显示，用户可以直接修改。

### Inbox 整理动作

- 移动到 Today
- 指定日期
- 移动到项目
- 添加标签
- 设置优先级
- 转换为重复任务
- 放入 Someday
- 删除
- 批量归档

## 6.3 任务字段

每个任务建议包含以下字段：

| 字段 | 必选 | 说明 |
| --- | --- | --- |
| id | 是 | 全局唯一 ID |
| title | 是 | 任务标题 |
| description | 否 | Markdown 备注 |
| status | 是 | 未完成、已完成、已归档 |
| priority | 否 | 无、低、中、高 |
| start_at | 否 | 开始时间 |
| due_at | 否 | 截止时间 |
| reminder_at | 否 | 提醒时间 |
| repeat_rule | 否 | 重复规则 |
| project_id | 否 | 所属项目 |
| section_id | 否 | 所属分组 |
| assignee_id | 否 | 执行人 |
| tag_ids | 否 | 标签 |
| checklist | 否 | 清单项 |
| estimate_minutes | 否 | 预计耗时 |
| actual_minutes | 否 | 实际耗时 |
| created_by | 是 | 创建者 |
| created_at | 是 | 创建时间 |
| updated_at | 是 | 更新时间 |
| completed_at | 否 | 完成时间 |

### 任务状态

- Inbox
- Planned
- In Progress
- Completed
- Archived
- Deleted

首期界面可以只暴露“未完成”和“已完成”，其他状态放在内部模型中，避免用户学习成本过高。

## 6.4 Today 今日视图

Today 是默认首页。

建议分为四个区块：

- 已逾期
- 上午
- 下午
- This Evening

如果任务设置了具体时间，则按时间排序。

如果任务只有日期，没有具体时间，则放在“全天任务”区域。

### 主要操作

- 完成任务
- 拖拽排序
- 改变时间
- 移动到其他日期
- 添加提醒
- 批量完成
- 批量移动
- 进入专注模式
- 查看当天日历事件

### 设计要求

Today 页面不能默认显示过多设置项。

任务标题应当成为视觉主体，其他信息以小标签、颜色和图标呈现。

---

## 6.5 Upcoming 未来视图

Upcoming 用于查看未来��划。

建议支持：

- 按天查看
- 按周查看
- 按月查看
- 日历视图
- 列表视图
- 拖拽调整日期
- 显示重复任务
- 显示截止日期
- 显示日历事件

桌面端适合列表和日历并行展示。

手机端默认使用时间轴列表，点击日期之后进入当天任务。

## 6.6 Projects 项目

项目需要支持：

- 项目标题
- 项目描述
- 项目颜色
- 项目图标
- 项目截止日期
- 项目成员
- 项目进度
- 项目分组
- 项目归档
- 项目共享
- 项目视图切换

视图建议包括：

- 列表视图
- 看板视图
- 时间线视图
- 日历视图

首期优先实现列表视图和看板视图。

### 项目进度

项目进度可以按照已完成任务数量计算。

如果项目有清单任务，应当以任务完成情况为主要依据。

进度计算规则需要在产品中保持一致，避免用户看到的进度和实际任务状态不一致。

---

## 6.7 重复任务与提醒

重复任务是任务产品中非常重要的一部分。

需要支持：

- 每天
- 每周
- 每月
- 每年
- 工作日
- 每周指定日期
- 每月指定日期
- 自定义间隔
- 截止日重复
- 完成后重复

### 例子

- 每天 9 点检查邮件
- 每周一、周三、周五跑步
- 每月 1 日提交报销
- 每完成一次后 7 天再次提醒

### 完成规则

重复任务完成后，系统生成下一次实例。

用户可以选择：

- 只完成当前一次
- 完成当前及后续任务
- 跳过本次
- 修改整个重复规则

---

## 6.8 标签与过滤器

标签用于跨项目检索。

建议预置标签：

- 工作
- 家庭
- 等待
- 电话
- 电脑
- 外出
- 高优先级

用户可以自定义标签。

过滤器支持组合条件：

- 标签
- 项目
- 区域
- 优先级
- 日期
- 是否逾期
- 执行人
- 是否有附件
- 是否已完成

示例过滤器：

```text
工作 + 高优先级 + 今天
等待 + 不是已完成
有截止日期 + 未来七天
```

## 6.9 搜索

搜索需要覆盖：

- 任务标题
- 任务备注
- 项目名称
- 标签名称
- 评论内容
- 附件名称
- 完成人
- 创建人

桌面端支持全局快捷键唤起搜索。

手机端支持顶部搜索和语音搜索。

搜索结果需要展示任务所在位置，用户可以直接跳转到项目或日期。

---

## 6.10 专注模式

专注模式用于执行一个任务。

首期支持：

- 25 分钟番茄钟
- 50 分钟专注
- 自定义时长
- 暂停
- 结束
- 自动记录实际耗时
- 完成任务
- 进入下一个任务
- 专注历史

专注模式不应该强行绑定番茄钟。用户可以只使用计时器，也可以关闭计时。

---

## 6.11 习惯

习惯属于第二阶段功能。

建议支持：

- 每天习惯
- 每周习惯
- 目标次数
- 连续记录
- 完成率
- 提醒
- 统计
- 跳过
- 补记

习惯与任务要保持清晰区分。

任务代表一次性工作，习惯代表周期行为。

## 6.12 协作

共享项目首期支持：

- 邀请成员
- 指派任务
- 评论
- @成员
- 附件
- 活动记录
- 完成通知
- 权限控制
- 退出共享项目

团队版本再加入：

- 团队工作区
- 成员管理
- 成员分组
- 角色权限
- 账单管理
- 审计日志
- 组织设置
- 域名邀请
- 单点登录

## 6.13 同步与离线

同步是整个产品的基础能力。

### 离线行为

离线时用户仍然可以：

- 创建任务
- 编辑任务
- 完成任务
- 调整日期
- 添加标签
- 修改项目
- 查看最近缓存的数据

### 同步机制

客户端维护本地变更队列。

每条变更包含：

- mutation_id
- client_id
- entity_id
- entity_type
- operation
- payload
- created_at
- base_version

服务端通过 mutation_id 保证幂等。

### 冲突处理

首期采用以下规则：

- 服务器保存对象版本号
- 客户端提交时携带 base_version
- 版本一致时直接写入
- 版本冲突时尝试合并字段
- 标题和备注冲突时保留双方副本
- 用户可以在冲突提示中选择版本

用户不能因为同步冲突而丢失任务内容。
