# Todo List 全平台产品研发项目全案
本文档为Todo List任务管理工具的完整研发执行方案，涵盖产品调研、PRD设计、技术架构、测试体系、DevOps部署五大核心模块，统一团队研发标准与交付规范，面向全体项目成员同步执行依据。

## 一、产品调研与产品需求文档（PRD）
### 1.1 核心竞品调研
选取行业内两款标杆产品作为功能与商业化参考，提炼共性能力与差异化优势：
#### 1.1.1 功能参考基准
- **Things 3**：苹果生态经典GTD工具，主打极简设计与纯原生体验，核心能力包括区域/项目/标签三级分类、自然语言快速录入、提醒与重复规则、专注模式、日历深度集成、iCloud无缝同步。优势是交互流畅、无冗余功能，劣势是仅覆盖苹果生态、无协作能力。
- **滴答清单**：国内全平台综合型效率工具，覆盖全场景任务管理，核心能力包括多视图切换（列表/看板/日历/甘特图）、习惯打卡、番茄专注、轻量团队协作、智能提醒、微信消息导入、全端实时同步。优势是功能全面、适配平台广，劣势是信息密度高、基础版限制较多。

#### 1.1.2 付费模式参考
- Things 3：采用**买断制**，Mac端、iPhone/iPad端分别独立售卖，一次付费永久使用，无内购、无订阅、无广告。
- 滴答清单：采用**免费+订阅制**，免费版开放基础功能并设置任务数量上限，高级会员按月/年付费解锁全部进阶功能、云端存储空间与协作权限。

### 1.2 产品定位与目标用户
- **产品定位**：一款轻量高效、跨端同步的通用任务管理工具，兼顾新手易用性与效率玩家的进阶需求，覆盖个人日程、学习规划、工作拆解全场景。
- **目标用户群体**：
  1. 学生群体：课业安排、考试复习规划、日常事项提醒
  2. 职场新人：工作任务拆解、日程对齐、待办事项跟进
  3. 效率爱好者：GTD实践、多端同步、个性化管理诉求
  4. 小型团队：轻量任务共享、进度同步与协作对齐

### 1.3 完整功能体系与付费规则
#### 1.3.1 功能分层设计
- **基础核心功能（免费版全量开放）**
  - 任务全生命周期管理：创建、编辑、删除、标记完成，支持标题、描述、截止日期、优先级、备注属性
  - 分类体系：任务清单、标签、文件夹三级分级管理
  - 提醒与重复：单次到期提醒、按天/周/月/年自定义重复规则
  - 基础视图与筛选：列表视图、按属性排序、多条件筛选
  - 账号与同步：账号体系下多端云端数据同步
  - 基础数据统计：每日任务完成量、完成率趋势展示

- **进阶增值功能（付费版解锁）**
  - 多视图模式：看板视图、日历视图、时间线视图
  - 专注与习惯：番茄钟专注、专注时长统计、习惯打卡与连续记录
  - 高级能力：任务附件上传、智能清单自动归类、自定义筛选规则
  - 数据与备份：CSV/Excel格式导出、数据备份与恢复
  - 协作能力：共享清单、任务指派、评论互动
  - 第三方集成：系统日历、笔记类工具联动

#### 1.3.2 付费规则设计
采用「免费基础版 + 会员订阅制」为主、桌面端买断为辅的商业化方案：
- 免费版：开放全部基础核心功能，单账号任务上限500条，单清单任务上限200条，提供基础同步能力。
- 高级会员：支持按月/按年订阅，解锁全部进阶功能，解除任务数量限制，扩容云端附件存储空间，享受优先客服支持。
- 桌面端终身版：针对桌面端用户提供一次性买断选项，权益与订阅会员一致，仅覆盖单设备授权。

### 1.4 PRD端侧设计规范
采用**两套设计体系、覆盖五端形态**的设计策略，保证体验一致性与平台适配性：
#### 1.4.1 大屏端设计体系（Web端 + 桌面端共用）
适配设备：PC浏览器、Windows/macOS桌面应用
- 布局逻辑：三栏式固定布局，左侧导航栏（文件夹/清单/标签/智能清单）、中间主内容区（任务列表/视图切换/批量操作）、右侧详情面板（任务编辑/属性设置/附件评论），顶部为全局搜索与操作栏。
- 交互特性：高信息密度展示，支持全局键盘快捷键、右键菜单、拖拽排序、批量选中操作，适配鼠标键盘高效操作场景。

#### 1.4.2 小屏端设计体系（手机端 + Pad端共用）
适配设备：iOS/Android手机、平板设备
- 布局逻辑：手机端采用底部Tab导航（首页/清单/统计/我的），悬浮按钮快速新建任务，自上而下信息流布局；Pad端适配分栏布局，左侧清单导航+右侧任务列表，兼顾大屏空间利用率与触控体验。
- 交互特性：触控优先设计，支持侧滑呼出操作、长按拖拽、下拉刷新、语音输入，保证单手可完成核心操作。

## 二、整体技术架构设计
### 2.1 架构总览
项目采用**前后端分离 + 多端适配 + 容器化部署**的分层架构，代码层基于pnpm Monorepo统一管理，前端覆盖Web/H5、移动端、桌面端三端形态，服务端提供多语言技术栈实现，基建层基于Docker标准化编排，实现全链路研发交付标准化。

### 2.2 代码仓库架构：pnpm Monorepo
基于pnpm workspace实现单仓库多项目管理，统一依赖版本、共享公共代码、简化构建流程，仓库目录规范如下：
```
todo-list-monorepo/
├── packages/                # 前端业务模块
│   ├── web/                 # Web端 + H5端（React + Vite）
│   ├── mobile/              # 移动端（React Native）
│   ├── desktop/             # 桌面端（Electron Forge）
│   └── shared/              # 前端公共层：类型定义、工具函数、通用组件
├── servers/                 # 服务端业务模块
│   ├── nestjs-server/       # NestJS 技术栈实现
│   ├── springboot-server/   # Spring Boot 技术栈实现
│   └── fastapi-server/      # FastAPI 技术栈实现
├── docker/                  # Docker 容器化配置
│   ├── compose/             # 服务编排（Docker Compose）
│   └── dockerfiles/         # 各服务镜像构建文件（Dockerfile）
├── tests/                   # 统一测试用例库
│   ├── unit/                # 单元测试用例
│   └── integration/         # 集成测试用例
└── package.json             # 全局依赖、脚本与工作空间配置
```

### 2.3 前端技术栈体系
#### 2.3.1 Web端 / H5端
- 核心框架：React 18 + TypeScript
- 构建工具：Vite 5
- 路由方案：React Router v6
- 状态管理：Zustand（全局轻量状态） + React Query（服务端状态管理）
- UI组件：Ant Design（Web端） / Ant Design Mobile（H5端）
- 样式方案：Tailwind CSS + CSS Modules
- 请求层：Axios + 统一拦截器与错误处理

#### 2.3.2 移动端（iOS / Android）
- 核心框架：React Native + TypeScript
- 跨端引擎：React Native 0.70+
- 路由方案：React Navigation
- 状态管理：Zustand + React Query
- UI组件库：React Native Paper
- 原生能力：封装系统通知、相机、本地存储等原生模块

#### 2.3.3 桌面端（Windows / macOS）
- 核心框架：Electron Forge + React 18
- 渲染层：复用Web端核心业务代码与组件，保证体验一致性
- 主进程：封装Electron原生能力（窗口管理、系统通知、本地文件操作）
- 打包分发：Electron Forge构建Windows安装包（.exe）、macOS安装包（.dmg）

### 2.4 服务端技术栈体系
服务端提供三套独立语言技术栈实现，均遵循统一接口协议与数据模型，可按需选择部署。
#### 2.4.1 NestJS 技术栈
- 核心框架：NestJS 10 + TypeScript
- ORM框架：Prisma
- 接口规范：RESTful API，可选支持GraphQL
- 认证授权：JWT + 权限守卫
- 扩展能力：中间件、拦截器、过滤器插件体系

#### 2.4.2 Spring Boot 技术栈
- 核心框架：Spring Boot 3.x + Java 17
- ORM框架：MyBatis-Plus
- 接口规范：RESTful API
- 认证授权：Spring Security + JWT
- 构建工具：Maven

#### 2.4.3 FastAPI 技术栈
- 核心框架：FastAPI + Python 3.10+
- ORM框架：SQLAlchemy 2.0
- 接口规范：RESTful API + 自动生成Swagger文档
- 认证授权：OAuth2 + JWT
- 性能特性：原生异步支持，高并发场景高效处理

### 2.5 基建层与中间件
#### 2.5.1 Docker 容器化体系
统一基于Docker实现环境标准化，分为两大模块：
- 镜像构建：`docker/dockerfiles/` 目录下为每个服务端程序编写独立Dockerfile，采用多阶段构建优化镜像体积。
- 服务编排：`docker/compose/` 目录下通过Docker Compose统一编排所有业务服务与中间件，支持一键启动全套开发与生产环境。

#### 2.5.2 核心中间件
均采用官方最新稳定镜像，保证安全性与兼容性：
- 业务数据库：PostgreSQL，存储用户、任务、清单、协作等核心业务数据。
- 缓存数据库：Redis，用于会话缓存、热点数据缓存、接口限流与轻量消息队列。

## 三、QA 自动化测试体系
### 3.1 测试体系总览
建立**单元测试 + 集成测试**两级自动化测试保障体系，覆盖前端交互、服务端逻辑、端到端流程全链路，保障产品功能正确性与迭代稳定性。
- 单元测试：基于Vitest实现，覆盖代码单元逻辑，保障代码质量。
- 集成测试：基于Playwright实现，覆盖核心业务流程，验证前后端联调后的完整功能。

### 3.2 单元测试方案（Vitest）
#### 3.2.1 测试覆盖范围
- 前端层：公共UI组件、自定义Hooks、工具函数、状态管理逻辑
- 服务端层：Controller接口层、Service业务逻辑层、数据访问层、工具类
- 公共层：共享类型定义、通用工具函数、协议解析逻辑

#### 3.2.2 核心用例拆解
1. **任务管理模块**：任务创建必填项校验、属性赋值正确性、重复任务规则生成、任务状态流转逻辑、删除级联处理、多条件筛选与排序准确性
2. **用户与权限模块**：注册登录账号校验、JWT生成与校验逻辑、未授权访问拦截、不同角色权限边界验证
3. **数据同步模块**：多端数据一致性校验、增量同步逻辑、并发冲突处理机制
4. **数据操作模块**：数据库增删改查正确性、事务回滚机制、异常场景容错处理

### 3.3 集成测试方案（Playwright）
#### 3.3.1 测试覆盖范围
覆盖Web端、H5端核心业务流程的端到端验证，模拟真实用户操作路径，验证前后端交互、数据流转的完整性。

#### 3.3.2 核心流程用例设计
1. 账号全流程：注册 → 登录 → 个人信息修改 → 退出登录
2. 任务核心链路：新建任务 → 设置截止日期/标签/优先级 → 标记完成 → 取消完成 → 删除任务
3. 清单管理流程：新建清单 → 移动任务至目标清单 → 重命名清单 → 删除清单（级联任务处理验证）
4. 视图与筛选流程：按标签/日期/优先级筛选 → 切换列表/看板视图 → 批量选中操作任务
5. 重复任务流程：创建每日重复任务 → 验证周期内任务自动生成 → 关闭重复规则
6. 异常边界场景：网络中断重连、无权限路径访问、非法值输入等容错验证

## 四、DevOps 构建发布与部署体系
### 4.1 交付流程总览
遵循「构建 → 制品管理 → 部署」的标准化交付链路：
1. 代码提交后触发自动构建，前端生成静态资源或安装包，服务端生成Docker镜像。
2. 服务端镜像推送至DockerHub镜像仓库，端侧产物归档管理。
3. 通过SSH连接阿里云服务器，拉取最新镜像并完成容器重启与服务更新。
4. 移动端、桌面端安装包输出为交付物，由负责人手动分发至对应应用平台。

### 4.2 构建打包策略
#### 4.2.1 前端各端构建
- Web端 / H5端：执行构建命令生成dist静态资源目录，可直接部署至静态服务器，或作为桌面端渲染层资源。
- 移动端：Android构建生成APK安装包；iOS构建生成IPA安装包（需配合苹果开发者证书与描述文件）。
- 桌面端：Electron Forge分平台构建，输出Windows.exe安装包、macOS.dmg安装包。

#### 4.2.2 服务端镜像构建
基于各服务对应Dockerfile执行多阶段构建，生成轻量化业务服务镜像。镜像统一命名规范：`[命名空间]/todo-[服务名]:[版本号]`，同时打latest标签与对应版本号标签，支持版本追溯与回滚。

### 4.3 云端部署方案
#### 4.3.1 镜像仓库推送
构建完成的服务端镜像，自动推送至DockerHub公共镜像仓库，作为统一制品分发源。

#### 4.3.2 阿里云服务器部署
1. 通过SSH协议连接阿里云目标服务器，采用账号密码方式完成授权认证。
2. 执行Docker命令拉取DockerHub上的最新版本镜像。
3. 基于Docker Compose重启对应服务容器，实现服务平滑更新。
4. 调用健康检查接口验证服务可用性，确认部署成功。

### 4.4 端侧产物交付
- 移动端：输出Android APK安装包、iOS IPA安装包，附带版本说明文件，由项目负责人上传至应用分发平台。
- 桌面端：输出Windows.exe、macOS.dmg安装包，可直接内部分发或上传至软件下载渠道。
- Web端：静态资源包可直接部署至Nginx静态服务器，或接入CDN实现全球分发。
